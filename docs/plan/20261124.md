## §0 结论先行

**一句话**：OpenBuddy 已经覆盖 WorkBuddy 单用户桌面主链路的约 **80%**；差距不再是"有没有对话/审批/产物"，而是 **设置中心深度、输入框状态细节、安全与产物生态、i18n 与设计令牌的系统化**。

**九个判断**

1. **主链路已对齐，长尾差距明显**：对话、流式、审批、分支、产物工作台、专家/技能/连接器、自动化、记忆、项目、手机接入都有真实实现；但 WorkBuddy 的 60 个设置配置域、12,692 条中文本地化、296 个设计令牌，OpenBuddy 分别只有 13 个设置分区、1,204 条、99 个。
2. **设置中心是当前最大结构性缺口**：WorkBuddy 设置按"设置 / 功能 / 数据与安全 / 关于"分组，带搜索与锚点；OpenBuddy 是 13 个平铺分区，无搜索、无分组，且缺通知、网络代理、存储与保留、系统授权、默认打开方式、工作空间路径、对话流展示、辅助任务模型等高频面板。
3. **输入框有"契约先行、UI 未接"的问题**：`voice-contract.ts` 已定义 ASR/TTS provider，但全仓没有任何 UI 调用；Composer 中有"成本预估"注释，但没有实现。这类"注释即对齐"会制造虚假完成度。
4. **安全仍停留在"逐次审批 + 受保护路径"**：WorkBuddy 安全中心有工具管控矩阵、沙箱文件/命令/网络策略、技能安全审查、审计日志、系统授权；OpenBuddy 安全面板只有权限规则与受保护路径。
5. **产物工作台预览面已不窄，但缺二次能力**：OpenBuddy 已支持 md/html/image/pdf/docx/pptx/sheet/csv/json/code/text/audio/video/binary；缺 drawio/excalidraw/mermaid 等图表、版本历史 UI、独立产物窗口、发布为应用、默认打开方式。
6. **国际化与设计系统是规模化短板**：OpenBuddy 2 种语言、1,204 键、228 个 tsx 文件含中文、6,534 处裸 px；WorkBuddy 20+ 语言、12,692 条中文键、296 个 `--wb-*` 令牌。继续按页面硬编码会让后续每次对标都变成改字符串。
7. **工程门禁已经有红灯**：`node tools/check-boundaries.mjs --check` 当前 `BOUNDARIES_FAIL`，size 违规从基线 4 涨到 7（`App.tsx` 1043 > 1042、`providers.ts` 626 > 611、gateway 多个文件超标）。在对标前应先修复，否则后续新增会持续挤压结构。
8. **逐屏走查显示视觉完成度不低**：首页、对话、审批、工作台、连接器、设置的截图都达到"可用且一致"的水平；真正的问题是入口可见性（技能/附件/权限藏在 `+`）、设置导航规模、产物二次能力，不需要重做视觉系统（详见 §3.4）。
9. **AI Chat 主链路已达行业基线，差在消息级细节**：流式、思考块、工具行、审批、分支、重试、计划、队列、上下文用量、产物卡都已具备；缺的是朗读、单条消息操作、来源卡、追问建议、对话内后台任务、逐轮 token、流式无障碍与划词范围（详见 §5.5）。

**三条主线**

- **主线 A（P0，体验一致性）**：设置 IA 2.0 + 首页/输入框状态补齐 + 产物二次能力。
- **主线 B（P0/P1，信任）**：安全中心 2.0（工具管控/沙箱策略/技能审查/审计/系统授权）。
- **主线 C（P1/P2，生态与规模化）**：自动化深化、团队、迁移导入、移动端远程、i18n 与令牌系统化。

### 本轮走查发现并修复的问题

1. **`+` 入队按钮被「思考等级」select 覆盖**（真实布局重叠，Playwright 命中测试报 `select intercepts pointer events`）：footer 原为固定 32px 单行，语音按钮 + token 估算徽章加入后横向溢出。改为 `flex-wrap: wrap` + `min-height`，挤出时换行而不是重叠。
2. **走查脚本三处选择器过期**：排队模式已从原生 `combobox` 改为 `radiogroup`；队列面板名称改为「排队中的消息」；用量/通知文案已随 W4.6/W5 更新。脚本已同步，未修改产品行为。
3. **`composer-wb-align.css` 从未被导入**：划词浮层、语音按钮、token 估算的样式因此全部未生效（浮层在截图里不可见）。已在 `app/main.tsx` 导入该文件，并移除其中与 `app.css` 重复的 `.wb-composer` 基础块，避免卡片外观漂移。
4. **发送组被拆行**：模型/思考/发送包成 `.wb-composer__sendgroup`，窄屏换行时整组靠右，不再把发送按钮单独甩到下一行。
5. **走查跑的是旧的主进程产物**：走查脚本导入 `dist-electron/main.js`，本轮新增的 `agent_delete_message` / `agent_continue` / `agent_clear_context` 在旧产物里不存在，真机调用直接报 `not_implemented: agent_delete_message`。教训：**改了 host / protocol 就必须先 `pnpm build:electron` 再走查**，否则测的是上一版。已把重建纳入本轮验证流程。
6. **`rewind_points` 用的是全会话条目，序号会错位**：它原先用 Pi 的 `getUserMessagesForForking()`（含其它分支上的旧版本），而界面按"当前对话里的第几条提问"取序号——一旦有重新生成或删除消息，序号就对不上，会删错消息。改为按**当前分支的投影**（`buildSessionProjection()`）枚举提问，与屏幕上的对话一一对应；`删除该消息` / `回退到此消息前` / `从这里编辑` 三处共用这套序号，因此一并修正。
7. **Pi 会把被截断的回答从模型上下文里摘掉**：Pi 在 `stopReason: "length"` 时自动写一条 `context_edit`（`replacement: null`）把半截回答移出上下文并尝试压缩重试。因此「继续生成」不能只是发一句"请继续"——模型根本看不见写了一半的内容。实现改为：先把这段内容用新的 `context_edit` 放回上下文，再让它从断点续写。
8. **渐变输入槽用错了页面**：上一轮把 `--wb-bg-input-slot-gradient`（WorkBuddy 的渐变输入槽）应用到了**聊天页**输入卡。核对 WorkBuddy 产物 CSS 后发现：渐变只在**首页** `.wb-home-composer__input-slot` 上，聊天页是 `.conversation-input__box .cr-input-box__main{background:0 0;border-radius:24px;padding:0}`——主区透明。已改为：聊天页主区透明（白卡 + 24px 圆角 + 发丝边），渐变槽只留给首页。
9. **状态 chip 出现范围比 WorkBuddy 宽**：初版在首页与聊天页都显示。核对 `main-content-core` 后确认 WorkBuddy 的两个 chip 由 `selectedWelcomeMode === "design"` 单一条件门控（`chat-*.js` 中 0 处 `wbStatusChips`），聊天页 chat input 根本没有它们。已收敛为「只在首页设计创意场景出现」，且状态前缀不再沿用到聊天页。
10. **状态前缀污染了用户气泡**：`【风格：专业严谨】` 直接拼在正文前面，气泡里连前缀一起显示。沿用既有的 `parseUserText` 剥离机制（与「想一想/问一问」隐藏块同一套），显示前剥掉，prompt 里保留。
11. **走查新增的检查点会污染后续断言**：状态 chip 用例需要"新建任务 → 首页设计场景"，而新建任务会把当前会话模型重置为首页默认模型，导致紧随其后的"切换失败保留原模型"断言失败。已把该用例挪到走查**最后**，并让首页/聊天页外观断言各自独立。
12. **只读 CSS 令牌会得出错的结论**：上一轮据 `--cr-internal-send-button-fill` 推断"发送按钮是透明底纯箭头"，实机放大后才发现是**灰色圆底 + 白箭头**（圆形在 SVG 里，空内容时 fill 为 `#0003`）。教训：WorkBuddy 细节必须以**实机 DOM/截图**为准，令牌只能作辅助；本轮改用 `--remote-debugging-port` + `connectOverCDP` 直接量 WorkBuddy 实机（`getComputedStyle`），量完再改代码，改完由走查断言锁死。

## §9 风险与依赖

1. **范围蔓延**：WorkBuddy 的 40+ 设置与 12,692 条文案是多年企业产品积累；本计划只取"高频、可本地验证"的面板，其余进 Phase 5/不做。
2. **宿主契约扩张**：Phase 1 新增约 12 个命令（proxy/storage/permissions/default-open/aux-model），必须同步 `commands.ts`、`host_capabilities`、`audit:ipc`、移动端降级策略。
3. **沙箱落地难度**：真正的文件/命令/网络隔离涉及引擎执行层与平台差异；Phase 2 先做"策略 + 拦截 + 审计"，OS 级沙箱单独立项。
4. **REA 证据边界**：WorkBuddy 是压缩产物，分包名与键能证明功能面存在，但不能证明每个交互细节；实现时以自测与用户反馈为准。
5. **文档漂移**：本轮已发现 TODO/FEATURE-STATUS/cu 文档过期；后续每个 Phase 结束必须更新唯一事实来源。
6. **i18n 返工**：如果继续在组件里硬编码中文，Phase 5 的扩面会指数级变贵；Phase 0 的基线脚本必须先落地。
