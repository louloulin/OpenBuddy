## §0 结论先行

1. **「compute use」不是一个功能，是四个口径**，必须分开显示、绝不混算：
   - **本地估算**（今天烧了多少 token / 多少钱）—— 已有，但按「会话最后一次在哪天」归日，不准；
   - **上游权威**（这一次调用真实花了多少）—— 今天**没有**，因为 Pi 不透出网关的 generation id；
   - **余额读数**（账户还剩多少额度、累计消费多少）—— 今天**没有**，这是最该先补的一块；
   - **预算**（日 / 月上限与进度）—— 今天只在渲染进程 localStorage 里，换窗口就丢。
2. **先补「余额读数」和「预算」，不要先追「逐次权威成本」**。前者一次 HTTP 就能拿到真账、零额外费用；后者要么依赖 Pi 透出 `providerMetadata.gateway.generationId`（当前 `pi-ai@1.6.0` 没有这个字段），要么走 Vercel 的 `/v1/report`（**官方计价 $5 / 1000 次查询**），性价比和合规性都更差。
3. **lumos 的可抄部分有三块**：`QuotaProvider` 适配器契约（`src/services/quota/types.ts`）、错误原因分类、预算与已花金额的分离。本文 §6 全部沿用它的形状，只把适配器从 DeepSeek 换成 Vercel AI Gateway。
4. **lumos 不可抄的部分**：它的服务端是 HTTP API + Zustand store + 五语言 i18n + SVG 图表（`desktop/src/features/tokenUsage/`）；OpenBuddy 是「宿主命令 + `invoke()` + 设置面板」，没有 i18n 框架，图表也没有现成依赖。照抄会引入一整套新的前端架构 —— **不抄**。
5. **AI Gateway 的 `/v1/models` 自带按 token 计价**（`pricing.input/output/input_cache_read/input_cache_write`）。OpenBuddy 现有的 `describeFetchedModel()` 只认 OpenRouter 的 `prompt/completion` 形状，所以网关模型此前**成本恒为 0**。补上这个形状是本次性价比最高的一处改动（§7 Step 2）。

## §1 需求界定：四个口径

| 口径 | 含义 | 数据来源 | 现状 | 优先级 |
|---|---|---|---|---|
| A 本地估算 | 本机这段时间用了多少 token / 多少钱 | Pi 的 `getSessionStats()` + 模型定价表 | 已有（`usage_snapshot`），但归日不准 | 先修归日 |
| B 上游权威 | 这一调用真实花了多少（网关账单口径） | AI Gateway `GET /v1/generation` | **无**（缺 generation id） | 二期 |
| C 余额读数 | 账户剩余额度 + 累计消费 | AI Gateway `GET /v1/credits` | **无** | **本次主线** |
| D 预算 | 日 / 月上限与已花进度 | C/A + 本地限额 | 只在渲染进程 localStorage | 本次主线 |

**边界（明确不做）**：

- 不把「估算」标成「账单」。面板上两栏分开，A 标注「按模型定价估算」，C 标注「上游账户读数」。
- 不做「阻断发送」的硬闸门 —— BYOK 场景下用户自己的钱，桌面端无权替他停。
- 不接 `/v1/report`（$5/1000 次查询 + $0.075/1000 次 tag 写入）：为一次本地面板付这个钱不划算，且 Hobby / Pro-trial 计划根本不能用该端点。
- 不做多端（手机端）同步预算：手机端通过 mobile-gateway 复用宿主命令即可，但 UI 一期不做。

### 2.2 缺口（逐条带证据）

| # | 缺口 | 证据 | 后果 |
|---|---|---|---|
| G1 | 用量按 **session 覆盖写**，归日按「该 session 最后一回合的日期」 | `packages/services/src/usage/usage.ts` 原 `record()` 直接 `file.sessions[id] = entry` | 跨天会话的花费全记到其中一天；「今天花了多少」偏大或偏小 |
| G2 | 费用 **只有估算**，且网关模型恒为 0 | `packages/services/src/providers/providers.ts:98` 只认 `pricing.prompt/completion` | Vercel AI Gateway 的 `pricing.input/output` 形状不被识别 → 成本算 0 |
| G3 | 没有**上游权威**口径 | 全仓库无 `providerMetadata` / generation id 相关代码 | 无法回答「网关到底收了我多少」 |
| G4 | 没有**余额读数** | 无任何供应商账单接口调用 | 用户只能自己开 Vercel 后台对账 |
| G5 | 预算阈值在**渲染进程 localStorage** | `apps/web/src/features/settings/usage-quota.ts`（`openbuddy.quota`） | 多窗口 / 多端不同步；宿主无法在发送前判断 |
| G6 | `UsageService` **没有单元测试** | `packages/services/test/` 下无 usage 用例 | 口径改了没有护栏 |
| G7 | 面板**没有权威/估算分列**，也没有空态/错误态分流 | `UsageQuotaPanel.tsx` 只有一条 `估算费用` | 估算被当成账单看 |

### 2.3 Pi 运行时的能力边界（决定 G3 能不能做）

- `ProviderConfigInput` 支持**注册期静态头**：`node_modules/@earendil-works/pi-coding-agent/dist/core/provider-composer.d.ts:58` → `headers?: Record<string, string>`（`authHeader` 在 :59）。
- **调用期**头变换存在但不由我们控制：`pi-ai/dist/models.d.ts:50` 的 `transformHeaders` 由 Pi 的扩展钩子 `before_provider_headers` 驱动（见 `chunk-KSDI5FD4.js` 的 `buildRequestOptions`），扩展钩子拿到的是**已装配好的 headers**，不带 session 上下文 → 逐会话打标在当前接入面上做不到「注册期静态」以外的粒度。
- `pi-ai@1.6.0` **没有 `providerMetadata`**（`grep -rl providerMetadata dist` 无命中），因此 AI SDK 那条 `providerMetadata.gateway.generationId` 路径在 Pi 里拿不到；流式响应里 AI Gateway 会把 generation id 注入首个内容块，但 Pi 的流解析会丢掉顶层 `id`。

> 结论：**G3（二期）不是写几行代码的事**，要么等 Pi 透出 provider metadata，要么绕开 Pi 直接自管网关请求。方案见 §7 阶段 C。

## §3 lumos 参考实现（可抄 / 不可抄）

### 3.1 三层结构

| 层 | lumos | 职责 |

| HTTP 出口 | `src/server/api/providerQuota.ts`（`GET /api/provider-quota?providerId=`）、`src/server/api/providerBudgets.ts`（`GET /api/provider-budgets`） | 桌面端可读、远端不可达（白名单） |
| 台账 | `src/server/services/usageLedger/`（按 `requestId` 去重、按 date×provider×model 汇总） | 每回合一行，追加写 |
| 桌面 UI | `desktop/src/features/tokenUsage/{QuotaPanel,ProviderQuota,TokenHero,TokenStreamChart,TokenHeatmap}.tsx`、`desktop/src/stores/quotaStore.ts`、`desktop/src/api/providerQuota.ts` | 余额卡、预算条、90 天柱图、52×7 热力图 |

### 3.2 值得抄的六条

1. **契约先行**：`QuotaProvider` 把厂商差异关在适配器里，主流程只认 `QuotaReading`。
2. **错误是「原因」不是「异常」**：`unauthorized`（凭据被拒）与 `network`（网不通）需要不同文案，`QuotaUnavailableError.reason` 就是干这个的。
3. **读数宽松、结构化字段 best-effort**：解析不出就是 `null`，**绝不用本地估算冒充上游账单**（lumos：CNY 余额时 `balanceUsd === null`）。
4. **预算与已花金额分离**：限额是配置，已花是台账算出来的。
5. **上游不缓存**：lumos 每次 `GET /api/provider-quota` 都是实时调用（`desktop/src/api/providerQuota.ts:42-44` 明确说明），由 UI 手动刷新控制频率。
6. **没有数据就不渲染**：lumos 的 `QuotaPanel` 无事件时返回 `null`，ProviderBudgets 无限额时返回 `null` —— 空卡片等于声称一个从未收到的读数。

### 3.3 不能抄的四处

| lumos 做法 | 为什么不能抄到 OpenBuddy |
|---|---|
| HTTP API + 远端白名单 | OpenBuddy 走宿主命令（`packages/protocol/src/commands.ts`）+ `invoke()`，没有远端 HTTP 面 |
| Zustand `quotaStore` + 事件总线 | OpenBuddy 渲染层直接 `invoke()` 拿快照，没有事件驱动的 store |
| 五语言 i18n（`settings.activity.*` 键位 + parity 断言） | OpenBuddy UI 是**中文硬编码**（见 `UsageQuotaPanel.tsx` 现有文案），引入 i18n 是另一个工程 |
| SVG 柱图 / 热力图 / 分享图 | OpenBuddy 无图表依赖；本次用「进度条 + 数字」表达预算即可 |

## §4 Vercel AI Gateway 事实卡（实网核对）

| 端点 | 鉴权 | 用途 | 本次用途 |
|---|---|---|---|
| `GET /v1/models` | **不需要** | 517 个模型，OpenAI 兼容格式，含 `context_window` / `max_tokens` / `pricing` | 模型导入 + 成本表（§7 Step 2） |
| `GET /v1/credits` | Bearer key | `{ balance, total_used, token_pass?: { remaining, resets_at } }`，金额是**字符串** | **余额读数（主线）** |
| `GET /v1/generation?id=` | Bearer key | 单次调用的 provider / latency / token / `market_cost` / `surcharge_cost` / `gateway_cost` | 二期（逐次权威） |
| `GET /v1/report` | Bearer key | 账户级支出报表，可按 day/user/model/tag/provider 分组 | **不做**（$5/1000 次查询，Hobby 不可用） |

- **Base URL**：`https://ai-gateway.vercel.sh/v1`；Anthropic Messages 走 `https://ai-gateway.vercel.sh/v1/messages`。
- **模型 id 形如 `provider/model`**：`anthropic/claude-sonnet-5`、`openai/gpt-4.1`、`google/gemini-2.5-pro`。
- **计价形状**（实测 `anthropic/claude-sonnet-5`）：`pricing.input=0.000002`、`output=0.00001`、`input_cache_read=0.0000002`、`input_cache_write=0.0000025`（**每 token 价**，与 OpenRouter 的 `prompt/completion` 同量纲不同键名）。
- **用量上报**（决定二期能否逐会话归因）：
  - 请求体：`providerOptions.gateway.user` / `providerOptions.gateway.tags`（≤10 个 tag，每个 1–64 字符；user ≤256）；
  - 请求头：`ai-reporting-user`（覆盖 body）、`ai-reporting-tags`（与 body **合并去重**）。
  - Pi 侧只有**注册期静态头**可用（§2.3），所以一期用 `ai-reporting-user: openbuddy-desktop` + `ai-reporting-tags: app:openbuddy` 做**应用级**归因，不假装能做会话级。
- **日志列表没有公开 REST**（只有 CLI `vercel ai-gateway requests`，回看 32 天）；`/v1/generation` 是唯一程序化单次查询口。
- **摄入是异步的**：`/v1/generation` 在记录就绪前返回 404，需要退避重试（官方示例重试 10 次 / 2s）。

## §5 目标架构

```
┌─ 渲染层 (apps/web) ───────────────────────────────────────────────┐
│ 设置 · 用量面板                                                     │
│  ├─ 估算栏（A）  ← usage_snapshot：今日/本月 token · 估算费用 · 按模型/专家 │
│  ├─ 权威栏（C）  ← usage_provider_quota：剩余额度 · 累计消费 · 读取时间   │
│  └─ 预算栏（D）  ← usage_budgets / usage_budget_save：日/月上限与进度    │
└───────────────▲───────────────────────────────┬──────────────────┘
                │ invoke()                       │ host command
┌───────────────┴───────────────────────────────▼──────────────────┐
│ 宿主 (packages/host/src/modules/host.ts)                            │
│  usage_snapshot · usage_provider_quota · usage_budgets · usage_budget_save │
└───────────────▲───────────────────────────────▲──────────────────┘
                │                               │
┌───────────────┴──────────────┐  ┌─────────────▼───────────────────┐
│ 服务 (packages/services/src) │  │ 引擎 (packages/engine/src)         │
│  usage/usage.ts   事件流台账  │  │  event-pipeline.ts:17 recordUsage │
│  usage/budgets.ts 限额持久化  │  │  → usageStats.record(entry)       │
│  usage/quota.ts    余额适配器  │  │  PiEngine.budgets = BudgetService  │
│  providers.ts     厂商目录     │  └─────────────────────────────────┘
└───────────────▲────────────────┘
                │ Bearer key（settings.secrets）
┌───────────────┴──────────────────────────────┐
│ Vercel AI Gateway  GET /v1/credits            │
└───────────────────────────────────────────────┘
```

**数据流（余额读数）**：面板「刷新」→ `usage_provider_quota(providerId)` → 宿主取 `settings.secrets.get("provider:<id>")` → 适配器 `GET /v1/credits` → 失败按 `unauthorized / http-error / network / protocol / missing-credentials` 分类 → 返回 `{status:"ok", reading}` 或 `{status:"unavailable", reason}` → 面板分状态渲染。

## §6 详细设计

### 6.1 协议层（`packages/protocol/src/usage.ts`）

```ts
export type UsageCostSource = "estimate" | "gateway";

export interface UsageEvent {           // 追加式每回合增量
  sessionId: string; at: string;
  providerId?: string; modelKey?: string; expertName?: string;
  tokens: { input: number; output: number; total: number };
  cost: number; costSource: UsageCostSource;
}

export type QuotaUnavailableReason =
  | "unsupported-provider" | "missing-credentials" | "unauthorized"
  | "http-error" | "network" | "protocol";

export interface ProviderQuotaReading {
  providerId: string; quotaProviderId: string;
  balanceUsd: number | null;
  balance: { currency: string; total: number | null } | null;
  spentUsd: number | null;
  extra: Record<string, string | number | null> | null;
  capturedAt: string;
}

export type ProviderQuotaResponse =
  | { status: "ok"; reading: ProviderQuotaReading }
  | { status: "unavailable"; reason: QuotaUnavailableReason };

export interface UsageBudget {
  providerId: string; name: string;
  limitDailyUsd: number; limitMonthlyUsd: number;
  spentTodayUsd: number; spentMonthUsd: number;
}
```

`UsageSnapshot` 增补：`byProvider: Record<string, UsageBucket>`、`cost: { estimated: number; authoritative: number }`。

### 6.2 服务层

- **`usage/usage.ts`**：`record()` 由「覆盖写」改为「覆盖写 + 追加增量事件」；`snapshot()` 优先按事件流聚合（**归日变准**），无事件流的老文件退回按 session 聚合（**向后兼容**）；新增 `providerSpend(providerId)` 供预算算已花。
- **`usage/budgets.ts`**（新）：限额存 `<userData>/pi/budgets.json`；`list()` 只返回**设过限额**的供应商；已花金额来自 `UsageService.providerSpend()`。
- **`usage/quota.ts`**（新）：`QuotaProvider` 契约 + `VercelAiGatewayQuotaProvider`（10s 超时、64 KiB 正文上限、数字字符串解析、错误分类）+ `getQuotaProviderForProvider(kind, id)` 注册表。
- **`providers/providers.ts`**：`describeFetchedModel()` 增加 AI Gateway 的 `pricing.input/output` 形状；新增 `vercel` 预设（`https://ai-gateway.vercel.sh/v1`，`chat_completions`，`bearer`）。

### 6.3 宿主与客户端

- 新命令（`packages/protocol/src/commands.ts`）：`usage_provider_quota` / `usage_budgets` / `usage_budget_save`。
- 宿主实现（`packages/host/src/modules/host.ts`）：取密钥用 `settings.secrets.get("provider:<id>")`；HTTP 走 `ctx.options.fetchImpl`（桌面端是 Electron `net.fetch`，**走系统代理**）。
- 客户端（`packages/client/src/api/usage.ts`）：`usageProviderQuota()` / `usageBudgets()` / `usageBudgetSave()`。

### 6.4 渲染层

面板分区（沿用现有 `.quota-panel__*` 命名与 `role="alert"` / `role="status"` 约定）：

| 区 | 数据 | 状态 |
|---|---|---|
| 估算栏 | `usage_snapshot` | loading / error / 空 / 正常 |
| 权威栏 | `usage_provider_quota` | 未配置该厂商 → **整块不渲染**；未读取 → 占位；失败 → 按 reason 给不同文案；成功 → 余额 / 累计消费 / 读取时间 |
| 预算栏 | `usage_budgets` | 无限额 → **整块不渲染**；有 → 日 / 月两条进度条 + 阈值输入 + 保存 |

## §9 风险与边界

| 风险 | 应对 |
|---|---|
| 估算 ≠ 账单 | 两栏分列并各自标注来源；权威栏只对有账单接口的厂商出现 |
| 归日口径 | 全仓库统一用 **UTC ISO 分桶**（与现有 `todayKey()` 一致）；本地时区跨日仍有偏差，文档注明 |
| 余额读取失败 | 分类为 6 种 reason，面板文案分流；**不重试风暴**（手动刷新） |
| 代理 | 宿主统一走 `ctx.options.fetchImpl`（桌面端 `net.fetch`），与既有 `/models` 探测同路径 |
| 密钥 | 复用既有 `SecretStore` + `safeStorage`；渲染层永远只看到 `••••`；宿主返回一律过 `secrets.redact()` |
| Pi 上游限制 | Pi 不透出 provider metadata → 二期成本高（§7 Step 6），一期不承诺逐次权威 |
| 计价意外 | 严禁在代码里调用 `/v1/report`；如未来要接，先在 UI 明确告知单价 |
| 工作区脏 | 本文只动自己列出的文件；`git status` 里那 62 处既有改动不碰 |
