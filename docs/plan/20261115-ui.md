## §0 结论先行

**现在在哪**：经过三轮打磨，对话区的"表面"已经接近第一梯队：按回合折叠、平滑流式、提问锚定、原地编辑、思考用时、长内容折叠、深浅主题对比度合格。差距集中在**表面之下**：

1. **产物系统基本是空壳**（P0）。右侧"产物"把读过的文件也算进去；预览只会把文件当 UTF-8 文本塞进 `<pre>`，Markdown 不渲染，图片、PDF、Office 文件是乱码；"变更"视图永远不出现；内置浏览器被自己的 CSP 挡住；点第一个产物就跳到文件树。一个写得很完整的 `FilePreview` 组件存在，但**没有任何地方引用**。
2. **改了文件就回不去**（P0）。"从这里编辑""重新生成"只回滚对话，磁盘上的文件保持被改后的样子；没有任何检查点。WorkBuddy 修改前自动备份、删除进回收站；Claude / ChatGPT 的代码模式都有 diff 与撤销。
3. **流式性能没有预算**（P0）。每个 token 都触发整段对话重渲染，正在输出的 Markdown 每 33ms 从头解析一遍（成本随长度平方增长），流结束时所有代码块重挂载（闪一下、展开状态丢失）。长任务和长会话会明显变卡。
4. **审批太粗**（P1）。只有"允许本次 / 本会话允许 / 拒绝"，没有"始终允许（存为规则）"、没有快捷键、拒绝不能附理由、后台任务的审批不会过期。
5. **输入框有假入口**（P1）。占位符写着"@ 引用对话文件"但没有 `@`；附件在两处重复显示；不能粘贴截图；PDF / Word / Excel 附件发送时报错；文本附件被计入两次 token。
6. **Pi 的大量能力没接到界面上**（P1）：会话树与分支切换、`exportToHtml`、按工具集切换（可直接做 Ask / Plan 模式）、`executeBash`、`abortRetry`、费用统计。

**北极星**：**对话里看过程，右侧看结果，每一步都能撤回，任何时候都不打断阅读。**

**优先顺序**（§7 详述）：U0 流畅性基线 → U1 产物系统 → U2 检查点与撤销 → U3 对话流补完 → U4 输入框 → U5 审批 → U6 后台任务与通知 → U7 扩展·技能·连接器 → U8 分享导出与窗口。U0 先做，因为后面每一项都会往对话流里加东西，没有性能预算只会越来越卡。

**从五家产品提炼出的共识**（本计划的设计依据）：
1. **过程收敛、结果外显**：工具噪音收成一行，可展开；产物以卡片和侧栏呈现（Claude、ChatGPT、WorkBuddy）。
2. **不打断阅读**：发送后提问留在视野内，用户上滑后绝不拽回（Claude）。
3. **运行中可继续说话**：排队可管理，插话有快捷键（Claude、Meta AI）。
4. **授权有粒度、有理由、有记忆**：允许一次 / 本任务 / 始终（存规则）/ 拒绝；删除永远确认（Grok Bot、Claude、WorkBuddy）。
5. **对产物的局部修改**：选中一段让 AI 只改这段；批注随下一条消息发送（Claude、ChatGPT、WorkBuddy）。
6. **安全默认**：改前备份、删除进回收站、完全访问需勾选风险（WorkBuddy）。
7. **诚实的状态**：需要你的输入、空闲计时、停止不等于失败、失败保留原文可重试（Claude）。
8. **插件不静默连接**：安装时预览权限，连接器逐个授权（Claude）。
9. **版本箭头在退潮**：ChatGPT 社区反馈箭头被移除、Claude 统一后不能从早先位置分叉，两家都转向显式的"分叉为新对话"。本计划对"重新生成 / 编辑"产生的同级分支保留"‹ 1/2 ›"（Pi 会话树天然支持，成本低），同时保留"分叉为新任务"。

## §3 体验原则与预算

**原则**
1. **Pi 原生**：凡 Pi SDK 已有的能力（会话树、导出、工具集、bash、重试、费用），直接接通，不在渲染层另造。
2. **一处真相**：产物、检查点、审批规则都由主进程持久化；渲染层只做视图。
3. **每一步可撤回**：任何会改文件的操作，在执行前留快照（§5.6）。这一条推翻 `20261115.md` §5 "不做文件回滚"，见 §9-D1。
4. **不打断**：新内容不拽动正在阅读的人；流结束不闪烁、不重挂载；弹层不抢焦点。
5. **诚实**：没接通的入口不显示；状态文字只描述真实发生的事。
6. **沿用 WorkBuddy 的文案习惯**，简体中文。

**性能预算**（U0 的验收标准，用 §8 的压测脚本测量）

| 指标 | 预算 | 现状（预估，U0 先测基线） | 第 2 轮实测（§11） |
|---|---|---|---|
| 流式输出时每帧主线程耗时 | p95 ≤ 8ms（60fps 下留出余量） | 随回答长度平方增长 | ✅ p95 6.3ms，长动画帧 0 |
| 单次 token 事件引起的组件重渲染 | 只渲染正在输出的那一块 + 状态行 | 整段对话 | ◐ 流式期间 DOM 写入 5788 次在当前回合内、138 次在外（状态行 / 底栏） |
| 流结束瞬间 | 无代码块重挂载、无布局跳动（CLS = 0） | 所有代码块重挂载 | ◐ 重挂载 0 / 12；CLS 0.0061（未到 0） |
| 打开 200 回合的长会话 | 首屏 ≤ 300ms，可交互 ≤ 800ms | 一次渲染全部 Markdown | ✅ 首屏 / 可交互 143ms（基线可交互 1029ms） |
| 大文件 `write`（1MB）参数流式期间 | IPC 总量 O(n)，界面不卡顿 | `tool_execution_update` 每次携带完整参数，O(n²) | ✅ 1.39MB = 内容的 1.33 倍（基线 4.83MB） |
| 输入框按键到字符上屏 | ≤ 16ms，流式中也一样 | 流式中受整段重渲染影响 | ◐ 输入延迟 ≤ 2.3ms、处理 ≤ 1.9ms；Event Timing 最大 32ms（空闲对照 16ms，见 §11 说明） |

## §5 目标规格

### 5.1 回合结构

```
[Logo] Buddy   正在处理 · 12s                                  ← 运行中的状态（完成后消失）
  › 已思考 4s                                                  ← 思考：一行，可展开
  拆解为 3 个步骤                                               ← 运行中逐条出现；完成后折叠成"已完成 · 用时 18s ›"
    ⌘ 执行命令  npm test                         3.2s ✓
    ✎ 修改文件  src/a.ts            +12 −3        0.1s ✓
    ✎ 写入文件  docs/report.md      写入中 · 12KB  …         ← 参数流式期间就显示路径与进度
    ┌ 写入文件命中询问规则，需要确认 ……（审批卡，见 5.4）┐
  最终回答（Markdown）
  ┌─────────────────────────────────────────────┐
  │ 📄 report.md      新建 · 2.1KB       预览   │            ← 本回合的产物卡片（最多 3 张）
  │ 📝 src/a.ts       修改 +12 −3        查看变更 │
  │ 查看所有产物（5）→                          │
  └─────────────────────────────────────────────┘
  [复制] [重新生成] [👍] [👎] [⋯]   ‹ 1/2 ›   14:02 · 用时 18s · 模型名
```

- **产物卡片**：只收本回合 write / edit 产生的文件，按路径去重。"新建"或"修改"由检查点判断（写入前文件不存在即"新建"），修改显示 +N −M。点卡片在右侧栏预览，次按钮"查看变更"打开 diff。多于 3 个时显示"还有 N 个"。
- **分支切换 ‹ 1/2 ›**：当这一回合的提问在 Pi 会话树里有同级分支（重新生成、编辑重发都会产生）时出现。切换调用 `navigateTree(该分支最新的叶子)`；运行中禁用。
- **提示行可展开**："上下文已压缩 ›"展开显示压缩摘要；"已切换到其他分支 ›"显示分支摘要；扩展的自定义消息有渲染器就渲染，没有就显示正文。
- **工具行**：
  - 参数流式期间解析部分 JSON，先显示 `path` / `command`；`write` 显示已写入的大小。
  - bash 运行中显示最后 3 行输出（等宽、灰色）；详情抽屉里完整输出超过 2000 行截断，并提供"保存为文件"。
  - 用户停止的工具行显示灰色"已停止"，不是红色失败。
- **重试**："请求失败，8 秒后重试（2/3）· 停止重试"，倒计时为真实剩余时间，"停止重试"调用 `abortRetry`。
- **空闲**：运行中 60 秒没有任何事件时，状态显示"已有 1 分钟没有新进展"，并持续计时。
- **失败**：错误卡保留（已实现）；失败回合的提问原文保留，可一键重试。

### 5.2 流式与渲染架构

| 层 | 做法 |
|---|---|
| 主进程 | `tool_execution_update` 与 `message_update` 一样瘦身：参数只在开始时发一次，输出只发增量；`toolcall_delta` 解析出 `path` / `command` / 已写字节数，节流后（≤ 10 次/秒）发出 |
| 事件进入渲染层 | IPC 事件先进队列，每个动画帧合并成**一次** store 更新 |
| Store | 结构共享：被忽略的事件返回原状态；`updateTool` 只替换包含该工具的那条消息；用户消息、已完成回合的对象引用保持不变 |
| 订阅 | ChatView 只订阅"节点 ID 列表 + 流式标记"；每个节点组件按 ID 订阅自己的消息；`TurnView` / `UserBubble` / `ToolCallCard` / `Markdown` 全部 `memo` |
| Markdown | **分块增量**：按代码围栏、空行分成块，已闭合的块按内容缓存，每帧只重新解析最后一个未闭合的块；`components` 映射保持稳定，`complete` 通过 context 传入，流结束不重挂载；mermaid / KaTeX 只在块闭合后渲染 |
| 平滑输出 | 追平后停止 rAF 循环，目标变化时再启动；`thoughtTimes` 随会话卸载清理 |
| 锚定 | `fitSpacer` 只在锚定期间运行；占位高度归零后释放锚定，不再测量 |
| 长会话 | 非最后一个回合加 `content-visibility: auto; contain-intrinsic-size: auto 600px`；仍不够时再上虚拟列表；回放 / hydrate 时不播放入场动画 |

### 5.3 输入框

```
┌──────────────────────────────────────────────────────────┐
│ [▣ 截图.png ×] [📄 需求.pdf ×] [技能 · xlsx ×] [批注 2 ×]      │  ← 附件 / 技能 / 批注只显示一次
│ 今天帮你做些什么？ @ 引用文件，/ 调用技能与指令                   │
│                                                          │
│ [+] [做一做 ▾] [默认权限 ▾]                ◔ 12%  [模型 ▾] [↑] │
└──────────────────────────────────────────────────────────┘
  📁 默认空间 ▾
```

- **+ 菜单**：上传文件 / 最近的产物 / 技能 / 连接器（本任务内逐个启停）。
- **模式**：做一做（全部工具）/ 想一想（只读工具 + 先出计划，见 5.8）/ 问一问（只读，不写文件不执行命令）。通过 `setActiveToolsByName` 切换工具集，按会话记住。问一问时输入框上方一行提示"只读：不会修改文件或执行命令"。
- **`@` 引用文件**：弹层检索当前工作区（忽略 `.git`、`node_modules` 等），最近的产物排在最前；选中后插入 chip，图片作为图片附件，其余作为路径引用。
- **粘贴 / 拖入截图**：主进程新增 `clipboard_save_image`，把剪贴板图片存到 `userData/attachments/` 并授权，返回路径；chip 带缩略图。
- **二进制附件**：PDF / Word / Excel 等不再报错，作为已授权的路径引用发送（"已附加文件：需求.pdf（2.1MB）"），由代理用工具读取；文本附件只内联一次，不再重复列为"相关文件"。
- **运行中**：
  - 回车入队；Ctrl/Cmd+回车立即插话（Alt+回车保留为别名）。
  - 队列每一行：放回输入框编辑 / 立即发送 / 删除，可拖动排序。
  - 输入框为空时按 Esc：先关闭弹层，再按一次停止回复。
- **↑**：输入框为空时编辑上一条提问（等同点该提问的"编辑"）。
- **思考档位**：模型菜单里的分段控件（关 / 低 / 中 / 高），模型不支持时置灰（`supportsThinking`）。
- **上下文环**：分项来自真实数据（系统提示词 / 工具 / 对话 / 技能与 MCP）；显示本会话费用（`getSessionStats().cost`，有价格数据时）；回合中也刷新；弹层里有"立即压缩"和"自动压缩"开关。
- **`!命令`**：以 `!` 开头时调用 `executeBash`，输出以命令卡片显示并记入上下文；运行中可停止（`abortBash`）。
- **草稿与历史**：按会话持久化（重启后恢复文字和附件）；`/` 菜单每次打开时刷新（5 秒缓存），流式中也可用。

### 5.5 产物系统

**数据**：主进程维护每个会话的产物索引 `ArtifactStore`。
- 来源：write / edit 工具的执行结果（不含 read / ls / grep / find）。会话加载时从 Pi 会话文件的**全部条目**重建，所以压缩过的历史也在；之后随 `tool_execution_end` 增量更新。
- 字段：`{ path, status: created|modified, firstTurn, lastTurn, toolCallIds[], added, removed, size, mime, checkpoints[] }`。
- 新增 IPC：命令 `artifacts_list`，事件 `agent://artifacts`。

**右侧栏**：
- 标签页：**产物**（每个打开的文件一个标签，可多开）/ **文件**（工作区文件树，单例）/ **变更**（diff，单例）。
- 快捷键：Ctrl/Cmd+T 新建（选择类型），Ctrl/Cmd+W 关闭，Ctrl+Tab 切换。
- 全屏按钮，Esc 退出；拖动分隔条调整宽度并记住；窗口窄时标签栏折叠成下拉；切换会话时关闭上一个会话的标签。

**按类型预览**：

| 类型 | 预览方式 |
|---|---|
| Markdown | 用对话同一套 Markdown 组件渲染；渲染 / 源码切换；大文件分块加载 |
| HTML | 主进程注册自定义协议 `ob-preview://`，只服务已授权工作区内的文件，预览页使用独立源 + 沙箱 iframe（允许脚本，不与应用同源）；CSP 只对这个协议放开 `frame-src`；渲染 / 源码切换、刷新、设备宽度（桌面 / 平板 / 手机） |
| 图片（png / jpg / gif / webp / svg） | `read_file_base64` → `<img>`，适应窗口 / 原始大小 / 缩放 |
| PDF | 经 `ob-preview://` 交给 Chromium 内置 PDF 查看器（需真机确认 Electron 45 在 iframe 中可用，见 §9-D2） |
| docx / pptx / xlsx | 第一版复用 `doc-preview.ts`：段落、幻灯片文本、表格；xlsx 以表格网格显示（高保真见 §9-D4） |
| csv / tsv | 表格，表头吸顶，前 1000 行 |
| JSON | 可折叠树 + 原文 |
| 代码 / 纯文本 | 高亮 + 行号，换行开关，面板内 Ctrl/Cmd+F 搜索 |
| 其他二进制 | 文件信息 +"用默认应用打开" |

**标题栏**：
- 左侧：文件名 + 状态（新建 / 修改 · 未保存 / 已保存）。
- 右侧最多 3 个按钮（编辑 / 打开 / ⋯）。⋯ 里有：用默认应用打开、在文件夹中显示、复制路径、**加入对话**（作为附件 chip 放进输入框）、另存为、复制内容（Markdown 文件复制 Markdown）、版本（5.6）。

**编辑与局部修改**：
- 文本类文件（md / txt / 代码 / json / csv / html 源码）可直接编辑：显示"未保存 / 已保存"，Ctrl/Cmd+S 保存；保存经 `write_text_file`（工作区校验），同时生成一个检查点。
- 文件在外部被修改时显示横幅"文件已在外部修改：刷新 / 另存为"（WorkBuddy）。
- 在预览或编辑器里选中文字，浮出两个按钮：
  - **让 Buddy 改这段**：输入框预填 chip `report.md L12–L20` + 选中原文，用户补一句要求后发送。
  - **批注**：批注收进输入框上方的"批注（N）"托盘，随下一条消息一起发送（Claude 的文件批注、ChatGPT 的 Annotations）。

**入口**：
- 回合内产物卡片（5.1）。
- 顶栏"任务概览"按钮显示产物数量，弹层列出本任务的产物和任务进程（各回合的状态与用时），对应 WorkBuddy 的"任务概览"。

### 5.6 检查点与撤销

- **何时拍快照**：write / edit 在**执行前**。现有审批门是 Pi 的 `tool_call` 钩子（`electron/agent/permissions.ts:28`，返回 `{ block, reason }`，在执行前生效）。另注册一个只拍快照、从不拦截的 `tool_call` 钩子，不论是否需要审批都会读取目标文件。文件不存在记为"无"；`tool_execution_end` 时记录新内容的摘要。
- **存储**：`userData/checkpoints/<sessionId>/` 下按 sha256 存内容，`index.json` 记录 `{ toolCallId, turnId, path, before, after, at }`。超过 20MB 的文件不拍快照并在工具行标注；总配额 500MB，按会话最后使用时间淘汰。
- **界面**：

| 入口 | 行为 |
|---|---|
| 产物 ⋯ → 版本 | 列出该文件的各版本（时间 · 由哪一步产生 · +N −M）；任选两版看 diff；"还原到此版本"（还原前先给当前内容拍快照） |
| 变更标签 | 本任务改过的文件，每个文件"最初 vs 现在"的 diff；按文件"还原"，或"全部还原" |
| 回合 ⋯ → 撤销本轮的文件改动 | 确认框列出将还原的文件；若某文件在之后又被改过（当前摘要 ≠ 本轮的 after），逐个提示"覆盖 / 跳过" |
| 编辑重发 / 重新生成 / 回滚到某处 | 确认框多一个勾选"同时还原这之后的文件改动（N 个文件）"，默认勾选，冲突同上 |

- **已知边界**：bash 命令修改的文件不知道目标路径，第一版不拍快照（见 §9-D8）；`rm` 删除的文件无法恢复。在"文件可能被命令修改"时，回合的产物区显示一行提示。

**真机验证中发现并修复的问题**

1. **并行写入丢检查点**：4 个写入几乎同时结束，`CheckpointStore.index()` 被并发加载两次，后一次覆盖了前一次的数组，新建的文件被显示成"修改"。改为缓存加载中的 Promise、索引写入按会话串行，并补测试。
2. **生产包 CSP 仍是 `frame-src 'none'`**：`scripts/build-electron.mjs` 往 `dist/index.html` 写入的 meta CSP 已存在时不会更新，HTML 预览被拦截（`ERR_BLOCKED_BY_CSP`）。改为替换已有 meta，策略与 `main.ts` 一致。
3. **PDF 预览空白**：应用的 CSP 响应头被套到了 Chromium 内置 PDF 查看器（`chrome-extension:`）上，它的 `chrome://resources` 脚本被拦截。CSP 头只加在 http / https / file 页面上。
4. **从磁盘打开的会话没有产物卡片**：ChatView 在 `agent_load_session` 完成前请求产物，拿到"会话未加载"后不再重试。改为 App 在会话加载完成后刷新；ChatView 只在回合结束时刷新。
