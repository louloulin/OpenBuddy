## §0 结论先行

1. **最大的问题不在 UI 皮肤，而在 AI 交互的控制语义。** 流式管线（MessagePort + 16ms 批 + rAF 合并）工程上是扎实的，但"一轮何时结束、谁能打断谁、审批是否真的拦得住"这三件事目前不可信：
   - 每个 `turn_end`（含 `stopReason: toolUse`）都发 `pi://complete` → 渲染层在**工具调用中途**就把 streaming 置为 false：停止按钮消失、输入框解锁、排队消息被发进仍在运行的会话。（已人工核验 `handle-session-event.ts:483-497`）
   - 15s 无文本 watchdog 不认工具事件 → 长命令（>15s）被误判"引擎无响应"而放弃。
   - 切换会话 / 定时自动化都会走 `replace()` **中止用户正在跑的回合**，且完成事件被会话过滤丢弃——静默中断。
   - 审批：`apply_patch` 写文件**零确认**；`apply_command` 在 `ctx.ui.confirm` 缺失时**放行**（fail-open，已核验 `apply-patch.ts:217`）、`cwd` 未校验；权限模式只作用于 hook 询问；审批 30s 不响应**自动拒绝**；停止不清理挂起审批。
2. **对话交互存在一批"会做错事"的 P0 缺陷**（均已核验代码路径）：空输入回车发送"你好"（首页还会新建会话）；文本中任何 `/`（如 URL）都会吞掉回车；审批提示在**每条**助手消息下重复渲染；快捷审批先从队列删除再调 IPC，失败即丢失审批；全局 Esc 会取消权限请求/跳过提问；⌘R 与菜单"重新加载"冲突且语义错（重发而非重新生成）。
3. **能力面对标 WorkBuddy 的真实缺口**：无联网搜索/抓取、无 Office 生成、终端非真 PTY、无图像生成、无浏览器自动化、无 autoMode、无托盘/全局快捷键/剪贴板图片；prod2 的 15 项中 **0 项完成、3 项部分**、**仓库 0 个 git tag（从未发版）**。
4. **信息架构膨胀**：6 个主导航 + 10 项"更多" + 助理 12 个子视图 + 设置 28 节（其中 18 节是企业管理）；"项目/空间/工作区/任务"、"资料库/我的文件/知识库/云存储"、账户×4 处、通知×3 处概念重叠；多处"承诺与实现不符"的假 affordance（右键无效、快捷键表有未绑定键、"换一批"不换、⌘K 承诺搜文件但不搜、引导 Tour 的 `data-tour` 锚点全仓为 0）。
5. **工程门禁"看起来绿"**：sheriff/ESLint/lint-tools/audit 均非阻断；`storage:boundaries` 本地已红（3 处违规，CI 会挂）；16 个测试文件不被 vitest 收集；Playwright 20 个 spec 不在 CI；**API Key 在 Linux/Windows 明文落盘**（`auth.json`）。

**一句话策略**：Phase 0 修"做错事"的 P0（2 周）→ Phase 1 重建 AI 交互可信度（回合状态机 + 审批体系）→ Phase 2 交互细节打磨到顶级 → Phase 3 IA 收敛与首次体验 → Phase 4 补齐对标能力（搜索/Office/PTY/图像）→ Phase 5 工程与发布。**每个 Phase 有硬验收，不过不进下一个。**

### 2.2 AI 交互全链路（现状）

| 阶段 | 现状实现 | 关键位置 |
|---|---|---|
| 输入 | Composer → `send()`：插件命令优先 → 附件路径拼"相关文件:" → 场景标签 `【x】` 前缀 → 有图走 `onSendContent` | `composer/send.ts` |
| 建会话 | 乐观会话 `__pending_*` → `piNewSession`（建会话 + **第二次 IPC** 设模型，非原子）→ `migrateSession` 换 id | `useOptimisticNewSession.ts`、`new-session-flow.ts`、`pi-client.ts:214` |
| 发送 | `agent:prompt` → 按会话注册 AbortController（**signal 未传入 SDK，形同虚设**）→ `session.prompt(text)` | `prompt-cycle.ts:104`、`agent-prompt.ts:118-151` |
| 流式 | 主进程事件 → `pi-stream-transport`（16ms/4096 批）经 MessagePort；**同时**再发一份 IPC 副本 + `dsh://rpc`（每事件一个 30s 定时器）+ `openbuddy://agent-event` 三路扇出 | `ipc/index.ts:922-1013` |
| 渲染 | `update-coalescer`（rAF 合并）→ session-store；text/thought/tool_call 合并；虚拟化列表（≥50 条启用） | `useAgentSession.ts`、`session-store.ts` |
| 工具 | `apply_patch`/`apply_command`/`memory_*`/`openbuddy_*` 11 个（其中 simplify/hashline_edit/worktree/automation **仅返回说明文字**）+ MCP `mcp__*` + email/calendar/team | `pi-extensions.ts`、`apply-patch.ts` |
| 审批 | 扩展 `ctx.ui.confirm` → `requestHookPermission` → UI 卡片；30s 未答 → deny | `hook-permission.ts`、`ui-request-resolver.ts` |
| 结束 | `turn_end/agent_end/agent_settled` → `pi://complete` → `setStreaming(false)` + 排队消息出队 | `handle-session-event.ts:483`、`useAgentSession.ts:548-586` |
| 错误 | `formatPiError` 子串启发式；`pi://error` **渲染层无订阅** | `error-format.ts`、`pi-client.ts` |
| 上下文 | Pi 默认压缩；OpenBuddy 调优参数**未传入 SDK**；context-guard 扩展因 `getContextUsage` 被桩为 undefined 而**失效** | `pi-extension-runner-bind-core.ts:109` |
| 记忆 | 不自动注入，模型需主动 `memory_recall`；`memory_save` 无确认写全局记忆 | `extensions/memory.ts` |
| 多智能体 | 子代理/团队是真 AgentSession；`maxDepth` 写入但从不读取 | `team-runner.ts` |
| 自动化 | 30s 扫描；执行时 `newSession` → **中止用户当前回合**；`permissionMode` 存了不生效 | `ipc/automations.ts:208` |
| 持久化 | 会话 JSONL；元数据 SQLite；rewind 快照**单文件全量重写、无修剪** | `rewind-snapshot.ts:79` |

## §5 顶级 AI 工作台的目标形态（North Star）

以"可信、顺手、精致"三条衡量每一项改动：

1. **可信（Trust）**
   - 回合状态单一真源：`idle → submitting → streaming ⇄ tool_running ⇄ awaiting_approval → settled | error | aborted`，主进程权威、渲染层只投影。
   - 停止永远有效且即时；后台会话不被打断，可并行；所有工具调用**先审批（或规则放行）、后执行、全留痕**。
   - 任何失败都有：可读原因 + 下一步动作（重试 / 去设置 / 切模型）+ 用户输入不丢失。
2. **顺手（Flow）**
   - 键盘全链路：回车/IME/Esc 语义精确无误伤；⌘K 是"命令 + 导航 + 搜索"统一入口；快捷键表即真相。
   - 审批就地完成：带 diff 预览、可"本会话总是允许"、不超时自动拒绝。
   - 首次 60 秒到达第一条真实回复：配置 Key → 测试连接 → 样例任务。
3. **精致（Craft）**
   - 流式到完成无跳变；长内容（代码/diff/工具输出）有上限、可展开、不卡顿；10k 消息滚动帧时 p95 ≤ 16ms。
   - 视觉 token 纪律（plan1030 契约门禁延续）；中英双语完整；a11y 基线（live region、焦点管理）。

**度量（每个 Phase 结束报告）**：首字延迟 p50/p95、流式渲染帧时 p95、工具回合"停止按钮可见率"=100%、审批丢失次数=0、发送失败输入恢复率=100%、首次到首条回复中位时长、i18n 字面量计数、E2E 通过数。

## §8 门禁与长期不变量（新增，叠加 plan1030 §6）

6. **组件不写字面量**：新增中文/英文 UI 字面量即红（存量棘轮）。
