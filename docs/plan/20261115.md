## §0 结论先行

1. **主链路能跑，但会"误杀"任务。** 发送、流式输出、工具执行、停止、切换模型和思考等级、Pi 的插话（steer）和追加（follow-up）、扩展 UI 表单、分叉，在真实主进程上都能工作。问题出在 `PiEngine` **同一时间只有一个会话**（`electron/agent/pi.ts:110-264`，`replace()` 第一步就是 `shutdown()`）。下面这些操作都会**静默中止**正在运行的任务：
   - 点侧栏里别的会话，或者再点一次当前会话
   - 去设置或别的页面再回来
   - 新建任务
   - 改技能或 MCP 配置

   WorkBuddy 的核心体验是**多个任务同时跑、在侧栏里随时切换**，所以**会话池（SessionPool）是本计划的头号架构项**。
2. **对话界面在"做错事"。** 已对照代码核实：
   - 空输入按回车会发出"你好"（`Composer.tsx:369`）。
   - 文本以 `/xxx` 结尾时（URL、路径）回车被吞（`Composer.tsx:433-438`）。
   - 带附件、技能或专家时，用户消息会**重复显示**，第二条是原始展开内容（`session-store.ts:146-149`）。
   - 一个回合里有几条 assistant 消息，就渲染几个头像和几组 👍👎（`ChatView.tsx:459-506`）。
   - 工具行只显示工具名，看不到命令、路径或 diff（`tool-renderers.ts:169-170`）。
   - 流式过程中每个 token 都要转发完整快照、同步读盘、解密全部密钥（`pi.ts:194` + `settings.ts:63-66`），**开销随回复长度平方增长**。
3. **大量界面"有壳无芯"。**
   - 渲染层调用了 **59 个主进程没有实现的命令**，用户看到的是原始英文 `not_implemented: xxx`。`ipc.ts:45` 里的中文兜底永远执行不到。
   - `App.tsx:448` 把"助理 / 专家·技能·连接器 / 自动化 / 资料库 / 灵感 / 云存储"统统拦成 toast"暂未在 Electron MVP 开放"。
   - WorkBuddy 主导航里有 3 项（专家·技能·连接器、自动化、助理），**我们 0 项可用**。
   - 重试被 `false &&` 写死禁用（`ChatView.tsx:499`）；"暂停"其实就是取消；计划、子代理、回溯、搜索面板要么永远不渲染，要么根本没挂载。
4. **补完有现成材料，大部分不用从零写。**
   - **Pi SDK 有现成接口**：`navigateTree` / `getUserMessagesForForking`（重试、编辑重发、回溯）；`setActiveToolsByName` 加官方示例 `examples/extensions/plan-mode`（计划模式）；`SessionManager.listAll().allMessagesText`（会话搜索）；`loadSkillsFromDir`（技能目录）；`appendSystemPromptOverride`（专家人设、记忆注入）。
   - **旧 Tauri 后端可以移植**：`git show cc4823f0^:src-tauri/src/{experts,skills_catalog,connectors_catalog,automations,agents_store,connector_cli}.rs`。数据结构和默认目录逻辑都能直接照搬。
5. **应用壳的硬伤**：
   - macOS 用了 `frame:false` 却没设 `titleBarStyle`，**没有红绿灯**（`electron/main.ts:29`）。
   - 项目页依赖 `window.prompt`，在 Electron 里无效（`ProjectsPanel.tsx:70`）。
   - 聊天页 5 个浮动按钮绝对定位在同一个点，互相叠住（`ChatView.tsx:336-446`）。
   - 归档的会话重启后又出现；会话标题不持久，重启后变成首条消息原文。
   - 快捷键页列的 Ctrl+N/K/,/B **一个都没有实现**。
   - 首次发消息会弹出"信任此目录？"，对象是应用自己的内部目录 inbox。
6. **真机走查发现了代码审计漏掉的硬伤**（真实 Electron 45.3.0 + 本地假模型服务，截图 90 张，见 §11）：
   - **重开会话时记录重复叠加**：每打开一次多一份，4 轮的会话显示成 8 轮。
   - **所有复制按钮都失败**：`main.ts:79-80` 一律拒绝权限请求，`clipboard.writeText` 报 NotAllowedError。
   - **深色模式基本不可用**：深色下 `--wb-bg-primary` 仍是白色，文字却变白，输入框、代码块、工具卡都是白底白字。
   - **"手动添加模型"必定报 TypeError**：`SettingsPanel.tsx:394`。
   - **带思考的流式输出首块重复**："修复建## 修复建议"。
   - **没有系统钥匙串时无法保存 API Key**，报错还被弹窗挡住，而且是原始英文。
   - 另外：每个会话 `agent_session_info` / `agent_session_usage` 各被调用约 70 次。
7. **工程基线是健康的**：两个 `tsc` 工程都是 0 错误；vitest 91 个文件，983/984 通过，唯一失败是时区相关的 `timeline-utils.test.ts:19`。但目前**没有门禁检查"渲染层调用的命令 ⊆ 契约"**，59 个缺口就是这么累积起来的。

**一句话策略**：Phase 0 止血（修 P0，1.5 周）→ Phase 1 会话池，实现多任务并行（1.5 周）→ Phase 2 对话视图 1:1（2 周）→ Phase 3 输入框 1:1（1 周）→ Phase 4 应用壳与侧栏 1:1（1.5 周）→ Phase 5 专家·技能·连接器 / 自动化 / 记忆补完（2.5 周）→ Phase 6 设置 1:1（1 周）→ Phase 7 清理与视觉统一（与各阶段并行）→ Phase 8 门禁与真机验收（贯穿全程）。**每个 Phase 都有硬验收，不过关不进下一个。**

                          ├─ Providers（BYOK，safeStorage 加密）
                          ├─ SkillsService（skillsOverride）

关键事实：
- 工具集固定为 `read/bash/edit/write/grep/find/ls/mcp__*`；`noPromptTemplates: true`；`noContextFiles: !trusted`。
- 应用数据放在 `userData/pi/`，不读 `~/.pi`。
- `agent_list_sessions` 每列一次，都要对每个会话文件执行一次 `SessionManager.open().buildSessionContext()`（`pi.ts:288-293`）。会话一多就是 O(n) 次全量解析。

## §3 目标规格：WorkBuddy 交互（一比一复刻基准）

> 以 WorkBuddy 5.9–5.11 的公开文档为准。凡是标"待实测"的，实施前需要有人在 WorkBuddy 客户端里截图确认，截图放 `docs/plan/shots-20261115/wb-ref/`。

### 3.1 整体布局 [S1][S4][S7]

- **三栏**：左侧栏 / 中间对话区（任务标题栏 + 消息列表 + 输入框）/ 右侧结果面板（可收起）。
- **对话区顶栏右侧**，从左到右依次是：
  - 对话内搜索（Ctrl/Cmd+F）
  - 分享
  - 历史：列出本任务的历次提问，点击跳到对应位置
  - 展开右侧栏

  另有"任务概览"浮层，列出本次对话的产物和任务进程 [S7]。
- **右侧栏是标签页**：产物 / 工作空间文件 / 变更 /（浏览器 / 终端，见 §9 决策）。标签栏右侧有"+"；Ctrl/Cmd+T 新建标签、Ctrl/Cmd+W 关闭标签；有全屏按钮，Esc 退出；窗口窄时标签栏折叠成下拉 [S6][S7]。

### 3.2 左侧栏 [S1][S3][S22]

- **上半部分**依次是：**新建任务 / 助理 / 专家·技能·连接器 / 自动化 / 更多**。国内版另有"项目"；"资料库"在 5.3.11 升为一级入口。
- **下半部分**：
  - **「任务」组**：标题右侧显示数量，默认只显示最近几条，底部"查看更多"。
  - **「空间」组**：按工作空间分组，可以展开；项目里有任务时才出现，图标和普通空间不同。
- **任务卡片**：标题 + 状态 + 最近更新时间。悬停时右侧出现三个按钮：**···、归档、置顶**。
  - **··· 菜单**：批量操作 / 打开文件夹 / 重命名 / 保存到工作空间 / 分享任务 / 删除任务。
  - **批量模式**：每一项前出现复选框；底部操作栏有"全选"和已选数量，按钮是删除、归档，右侧可关闭。
  - **工作空间这一行的菜单**：新建任务 / 打开文件夹 / 重命名 / 从列表中移除。
- **搜索面板**：按标题查找，结果右侧显示所属工作空间或时间。
- **筛选面板**：
  - 状态：全部 / 进行中 / 已完成 / 失败 / 待处理 / 规划中
  - 时间：全部 / 今天 / 近 7 天 / 近 30 天
  - 底部"重置筛选"
- **头像（最底部）**：菜单里有"设置"和"帮助与反馈"。

### 3.3 首页 / 新建任务 [S1][S30]

- 5.11 改版后：问候语 + **突出输入框** + 6 个场景胶囊。三大模式入口和示例提示词都已下线。
- 设置里有"专家与技能推荐"开关，开启后新建任务时会推荐专家和技能 [S19]。
- 胶囊名称、问候语文案：待实测。

### 3.4 输入框 [S1][S2][S8][S32][S35]

- **左下角**：
  - **+**：上传文件。也支持拖入文件，或用 Ctrl/Cmd+V 粘贴截图。桌面端菜单条目待实测。
  - **模式**：Craft 做一做（默认）/ Plan 想一想 / Ask 问一问。Ask 模式不加载写入和执行类工具。
  - **连接器**：图标，点开弹窗可以逐个启停。
- **右下角**：
  - **模型选择**：默认 Auto；下拉里有"自定义模型"分组和"配置自定义模型"入口。
  - **增强提示词**：闪光图标（属于新能力，不做，见 §5）。
  - **上下文用量**：灰色小圆环。悬停显示"4.9% · 49.4K/1000K"；点开看分项：系统提示词 / 工具 / 对话消息 / 连接器·MCP·技能。
  - **发送 / 停止**：运行中变成"停止任务"。
- **输入框下方元信息**：
  - **工作空间选择**：面板里有搜索 / 新建 / 打开本地文件夹。
  - **权限状态按钮**：默认显示"默认权限"；点开有"允许完全访问"开关。打开开关时弹出二次确认，列出将放开的能力（文件操作、终端命令、访问互联网），**必须先勾选风险确认**，然后点"允许完全访问"。
- **`/`**：技能和命令，打几个字母就模糊匹配；**`/compact`** 手动压缩上下文。**`@`**：引用文件。
- **其他**：发送后输入框高度恢复；草稿和附件可以恢复 [S28][S29]；Enter 发送，可以在设置里改。

### 3.5 对话视图 [S4][S8][S19][S31]

- **"简洁模式"默认开启**：工具调用过程折叠。
  - 运行中：显示阶段说明，例如"正在分析数据"。
  - 完成后：一行摘要"已完成"，可以展开查看步骤。旧文档 §18 截图里是"已完成 · 用时 Xs ›"。
- **权限确认** [S8]：
  - **标题按操作类型变化**，例如"执行命令命中询问规则，需要确认。"，同类还有读取文件、写入文件、删除文件、访问网络。
  - **对象单独一行**，标为"文件"或"网址"；太长会省略，点击弹浮窗看完整内容。
  - 右上角有"查看拦截规则"，点击跳到设置·安全中心并高亮对应规则。
  - 拒绝后这一步不执行，对话继续。
  - 按钮的确切文案和位置（模态还是嵌在对话流里）待实测；旧文档 §21.3 截图显示**嵌在对话流里，跟在工具行下面**。
- **错误**：一句人话 + 可展开的原始错误（5.9.4 起会显示原始错误）+ 建议"换模型重试"[S24][S28]。
- **连接引导卡片**：任务用到还没连接的服务时，输入框上方出现卡片（服务名 + 头像 +"连接"），授权完成后任务自动继续。授权失效时出现"连接器需要重新连接"卡片 [S13][S16]。
- **消息操作栏**：复制 / 重试 / 👍 / 👎 / ⋯，放在回合底部（以旧文档 §18 截图为准；官方文档没写，待实测）。
- **多任务并行**：侧栏里的任务各自显示"进行中"等状态，可以随时切换 [S1][S3]。

### 3.6 专家·技能·连接器 [S12]–[S16]

- **专家**：
  - 按行业分类浏览，也可以搜索。卡片显示能力、擅长领域、任务示例。
  - 点"召唤"会预填输入框，但**不会自动提交**。
  - "我的专家"：可以创建、修改、分享、删除。
- **技能**：
  - 页面上方是已安装，下方是推荐；悬停或点卡片上的"+"即可安装。
  - "添加技能"有三种方式：上传 / 查找 / 创建。上传后做安全检测，高风险的需要手动确认。
  - 每个技能有启用开关；支持搜索、卸载、批量卸载。
  - 技能分用户级和项目级。
- **连接器**：
  - 以卡片展示。状态圆点：绿色 = 已连接且开启，灰色 = 已连接但未开启，无圆点 = 未连接。
  - 卡片右侧有启停开关；已连接的卡片上有"去试试"；解绑要二次确认。
  - 右上角有"自定义连接器（MCP）"。

### 3.7 自动化 [S17][S18][S28]

- **页面**："定时任务 / 运行记录"两个标签，右上角"添加"。
- **表单字段**：名称、工作空间（默认 automation-xxxx）、提示词、模型和技能、专家与连接器、执行频率、有效期、权限设置。
- **执行频率**：
  - 单次：指定日期和时间。
  - 重复：每天 / 每周 / 每两周 / 每月 / 每年，加具体时间。
  - 间隔：每 N 小时，可以限定星期几。
- **管理操作**：运行记录（可以打开某次运行看输出）、测试运行（真实执行）、修改、暂停/恢复、删除。
- **其他**：任务完成发桌面通知；重启或休眠后会补跑。

## §5 原则与不做清单

**原则**
1. **能接就接**：先用 Pi SDK 或已有的主进程能力把界面接通。
2. **接不了就藏**：不保留任何会报错、点了没反应或显示假数据的入口。
3. **一处真相**：
   - 回合状态以主进程为准。
   - 会话标题、归档、置顶都由主进程持久化。
   - 快捷键页由实际的注册表生成。
4. **按 WorkBuddy 的文案习惯写**，统一用简体中文。
5. **每改一处交互都要有截图**（§8）。

**不做**（属于新能力，不在本计划范围内）
- 联网搜索的内置工具（改走 MCP）
- 增强提示词
- 终端标签页（PTY）
- 内置浏览器（见 §9-D4）
- 图像或视频生成
- 积分体系
- 云端网盘、腾讯文档、ima、乐享
- 团队协作和邀请
- 远程助理（微信、QQ 等 IM）
- 市场后端
- 专家团、子代理
- 文件回滚（Pi 不回滚文件，`rewind` 只回滚对话）

**不照搬**：WorkBuddy 的 Logo、插画、品牌色、文案里的产品名。

## §8 验收标准与长期不变量

1. **入口可用率 100%**：所有可见的按钮和菜单项都能完成承诺的动作。点遍全部入口，运行时审计显示 0 次 `not_implemented`。
2. **契约闭合**：渲染层调用的命令 ⊆ COMMANDS；EVENTS 里每一项都有发送方和接收方（8.1 门禁）。
3. **不误杀**：任何导航操作都不会中止后台任务。中止只来自用户点击"停止"，或者用户明确确认过。
4. **不丢数据**：发送失败时输入能恢复；重启后标题、归档、置顶、赞踩、草稿都还在。
5. **对话流的形态**：每个回合一个头像、一条动作栏；完成后折叠；审批卡跟在对应工具行下方；错误卡在回合内。
6. **性能**：长回复（5k token）时，主进程不再每个事件同步读盘；流式帧时 p95 ≤ 16ms ⚠（需要先建立测量手段）。
7. **每一项改动**：要有单测，或者 Electron 截图步骤；改动交互的必须两者都有。
8. **一致性**：没有中英混杂；不新增写死的颜色；深色模式下每一屏都截图检查。

### 10.4 会话池草案

```ts
interface Slot {
  id: string; session: AgentSession; manager: SessionManager; cwd: string;
  unsubscribe(): void; origin: "user" | "automation" | "ephemeral";
  busy: boolean; generation: number; cancelledGeneration: number; commandError?: string;
  transitioning: boolean; stale: boolean;               // 运行中遇到配置变更，结束后重建
  permissionMode?: "ask" | "auto" | "always-approve";   // 自动化任务覆盖全局设置
  lastActive: number;
}
class SessionPool {
  slots = new Map<string, Slot>(); opening = new Map<string, Promise<Slot>>();
  focused?: string;                                      // 文件操作和命令列表的默认目标
  limits = { maxLive: 6, maxRunning: 3, idleMs: 15 * 60_000 };
  open(manager, opts): Promise<Slot>;                    // 不影响其他会话；超出上限先淘汰最久未用的空闲会话
  send(id, ...); queue(id, ...); cancel(id); close(id);  // close = abort → session_shutdown → dispose
  reloadAll();      // 空闲的立即重建；忙碌的标记 stale，等 agent_settled 后再重建
  evictIdle();      // 回收：不忙、未聚焦、无待处理请求、空闲超过 idleMs
  status(id): "running" | "awaiting_input" | "idle" | "error";
}
```

- `subscribe` 回调在 `agent_start` / `agent_settled` 时更新 `slot.busy`，并发出 `agent://session-status`。
- `Permissions.extension(id, () => slot.permissionMode ?? config.permissionMode)`：无人值守时，ask 请求发通知，超时后拒绝。
- 风险 ⚠：
  - 两个会话在同一目录里同时写同一个文件（Pi 的 file-mutation-queue 作用范围没验证）。
  - N 个会话加 N 份 MCP 进程的内存开销。
  - 多个会话共享同一个 `ModelRuntime`，凭证并发刷新的行为没验证。
