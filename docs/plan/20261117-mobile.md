## 1. 产品形态分析

### 1.1 三端角色

| 端 | 角色 | 拥有什么 | 不做什么 |
|---|---|---|---|
| **桌面（Electron + Pi 引擎）** | 执行、配置、真相源 | 模型与密钥、工具执行、文件写入、终端、会话存储、索引、MCP/扩展/技能、工作台（Diff/产物/浏览器预览） | 不依赖手机存在；离线也能完整工作 |
| **手机（Expo）** | 在场、指挥、审批、回顾 | 设备凭证、缓存（会话/转录/outbox）、推送注册、生物识别、相机/麦克风/分享 | 不执行工具、不存密钥、不写桌面文件 |
| **网关（Bun）** | 配对与隧道 | 设备、配对码、隧道、推送派发、审计 | 不做业务逻辑、不存会话内容、不改协议语义 |

### 1.2 为什么不是“把桌面搬到手机”

| 约束 | 后果 | 手机的正确做法 |
|---|---|---|
| 屏幕与输入 | 终端、Diff、多文件编辑器无法在一列内用 | 只做**监督与决策**：状态、审批、摘要、单个产物预览 |
| 安全 | 密钥、文件写、shell 是高危面 | 这些能力永远留在桌面，手机只给“允许/拒绝” |
| 数据重力 | 索引、转录、工具产物在桌面 | 手机缓存最近会话，重连按 seq 补齐 |
| 电池与网络 | 长连接 + 轮询代价高 | 事件驱动 + 推送唤醒 + 前台才轮询任务 |
| 注意力 | 手机是“打断式”设备 | 把需要人的时刻（审批、失败、完成）推到手机，其余静默 |

### 1.3 手机端功能分层（决定做什么）

| 层 | 目标 | 典型功能 | 判定标准 |
|---|---|---|---|
| **Capture（随手发起）** | 3 秒内把想法交给电脑 | 新建任务、语音输入、拍照、文件引用、跟进建议 | 不需要理解代码，只需要“发出去” |
| **Supervise（在场监督）** | 知道它在干什么、能否继续 | 流式、思考、工具卡、队列、插话、任务面板、停止 | 5 秒内判断“正常/卡住/需要我” |
| **Decide（决策）** | 不打开电脑也能推进 | permission、UI 问询、目录信任、通知深链、通知内批准 | 决策后桌面立即继续 |
| **Review（回顾）** | 在路上看完结果 | 产物、检查点、分支、记忆、资料库、文件只读、分享 | 只读为主，写操作刻意克制 |
| **Configure-lite（轻配置）** | 不改桌面也能用 | 模型/思考档位、人格、自动播报、应用锁、通知偏好 | 不触碰密钥与全局配置 |

> 不符合以上五层的功能（MCP 管理、扩展安装、供应商密钥、终端、窗口控制）**不做**，
> 并通过 `host_capabilities` 在 UI 上完全隐藏，而不是点了才报错。

## 2. 手机 ↔ 桌面交互模型

### 2.1 连接与信任

```
桌面启动 ──(出站 WS, agent token, desktopId)──▶ 网关 ◀──(HTTPS/SSE, device token)── 手机
   ▲                                              │
   └───────── 手机命令经隧道转发到 PiBridge ───────┘
```

- 桌面**只做出站连接**，不开公网端口；网关地址与 agent token 由环境变量注入。
- 配对：桌面主进程用 admin token 生成 8 位码（绑定 desktopId）→ 手机扫码/手输 →
  `/pair/claim` 换 device token（scopes: read/write/approve）→ 存 SecureStore。
- 能力握手：手机拉 `/api/capabilities`（桥把 `host_capabilities` 改写成手机面）；
  **所有入口以能力表为准**，桌面未开放的整块不渲染。
- 撤销：桌面设置页吊销设备 → 手机收到 401 → 清配对并回到配对页；应用锁保护本地凭证。

### 2.2 会话生命周期

| 阶段 | 手机动作 | 桌面动作 | 事件/命令 |
|---|---|---|---|
| 新建 | 拉工作区列表（或默认 cwd）→ 选目录 | 校验模型与目录 → 建会话 | `agent_init` / `agent_list_workspaces` / `agent_new_session` |
| 对话 | 发送 / 排队 / 插话 / 中止 | 执行回合、推送增量 | `agent_send` / `agent_set_queue` / `agent_steer` / `agent_cancel` |
| 观察 | 渲染思考、工具卡、产物、用量 | 产生事件 | `agent://event`（seq + since 补齐） |
| 决策 | 审批卡片/问询卡片/信任卡片 | 等待并继续 | `agent://permission` / `agent://question` / `folder_trust_respond` |
| 结束 | 未读徽标、推送、可朗读 | settle、写历史 | `agent_settled` → 网关 live-status → 推送 |
| 回顾 | 检查点、分支、导出分享 | 提供树/检查点/导出 | `agent_tree` / `checkpoint_*` / `agent_export_jsonl` |

### 2.3 运行中三种输入语义（v3 必须明确）

| 用户意图 | 手机入口 | 桌面命令 | 语义 |
|---|---|---|---|
| 等它说完再发 | 默认发送 | `agent_set_queue` | 进入队列，回合结束后依次执行，可编辑/删除 |
| 现在就要改方向 | 长按发送 →「立即插话」 | `agent_steer` | 打断当前生成，按新指令继续同一回合 |
| 补充一个问题 | 长按发送 →「追问」 | `agent_follow_up` | 在当前回合后追加一个独立回合 |

> 离线下三者都不可用（队列在本地 outbox 只支持普通 `agent_send`），UI 明确禁用并解释。

### 2.4 审批的三条路径

1. **App 前台**：事件 → 内联卡片 → 允许/拒绝（可带原因）→ 桌面继续。
2. **App 后台/锁屏**：网关推送（含 requestId）→ 点通知深链回会话 → 卡片仍可回答。
3. **App 不可达**：桌面本地 UI 兜底；手机回来后从历史/事件补齐未决卡片（TTL 内）。

原则：**审批永不自动通过**；回答失败保留卡片并提示，不自动重试。

### 2.5 断线、重连与推送

- 手机 SSE 断线：指数退避重连，带 `since=seq`；缺口过大回 `resync` 拉快照。
- 后台：连接可断；桌面与网关不受影响；重连后补齐事件并更新未读。
- 推送只负责“叫人”，不承载内容真相；打开 App 后以快照/事件为准。
- `live-status` 由桥从事件流归纳，网关 watcher 派发 done/approval/scheduled。

### 2.6 分享与导出

- 单条回复：手机本地复制/朗读/分享（文本、Markdown；长图仅 dev build）。
- 整段会话：桌面 `agent_export_jsonl` / `agent_export_html` 产出 → 手机接收 →
  系统分享面板。手机不自行拼装会话真相。

### 2.7 多设备与多桌面（边界）

- 当前：一台手机 ↔ 一台桌面（一个 device token）；桌面可被多台手机配对。
- v3 不做“多桌面并行在线”，但**本地多 Pairing + 切换**已在 §9.12 实现：
  凭证本来就只存在手机上，切换不需要网关新接口。

## 10. 非功能目标

| 维度 | 目标 | 手段 |
|---|---|---|
| 交互延迟 | 发送→首个 token ≤ 桌面 + 1 RTT；审批点击→桌面继续 <1s | 事件直通、不轮询 |
| 冷启动 | 缓存首屏 <1.5s | SQLite 优先、按需加载转录 |
| 断线恢复 | <3s | since 补齐 + resync 兜底 |
| 耗电 | 后台不轮询 | 前台任务轮询、后台依赖推送 |
| 安全 | 密钥不出桌面；凭证在 Keychain；应用锁 | 主进程隔离、SecureStore、生物识别 |
| 隐私 | 网关不落内容；审计仅元数据 | 隧道转发、sqlite 只存设备/配对 |
| 可用性 | 所有图标有 label；字号跟随系统 | 阶段 F |

## 11. 风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 队列/插话语义版本不一致 | UI 与实际不符 | 以 `agent_get_queue` 回读为准；能力门禁 |
| 问询事件名不一致 | 卡片不出现 | 同时监听事件与内联 update；E2E 双路径 |
| 附件内存 | 8 张原图过大 | 选图即压缩 1600px/0.8 |
| 多桌面 | 曾以为需网关新接口 | 已按本地多 Pairing 实现（§9.12），网关零改动 |
| 分享原生模块 | Expo Go 不可用 | 文本先行；长图仅 dev build |
| 批量部分失败 | 状态不一致 | 逐条提示 + 刷新 |
| read 扩面 | 安全面变大 | 每条命令单独测试；写命令 fail-closed |

回滚：独立提交；能力门禁控制入口；本地设置键只增不改。
