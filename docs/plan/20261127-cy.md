## §0 结论先行

**v3 结论**：编排、证据门禁、报告规格、PPTX 导出与版式预览已打通（P1/P2-1/P2-2 完成）。用 3D 打印报告事实真跑一遍：29 页 / 14 表 / 5 图，16 类内容块覆盖 9 类，估值因缺定量输入而如实留空。剩余差距集中在**真实数据获取**与**文字体量**，见 §11。下文 §0 表格保留 v2（P0 后）的判断作为基线。

**（v2）方法论骨架 100%（9/9），输入模型与去伪精确已补齐（P0 完成），数据接入与成稿展示仍是 0。**

现有产业工具已把《产业分析与投资》讲义的分析骨架实现为确定性纯函数：PEST / 市场四维 / 产业链 SCP / 六维趋势 / 五力 / 利润池 / 企业画像 / 利润驱动 / 投资价值，加上已存的 DCF/DDM/可比/期权/技术面工具。P0 又补了数据适配器、证据注册表、扩输入模型与去伪精确。

**剩下的差距全部集中在「最后一公里」**：

| 层 | P0 后现状 | 仍缺 | 对标 6 份 PPTX 的直观结果 |
|---|---|---|---|
| **数据层** | 有 `IndustryDataset` 适配器（inline/json/web 三 provider），但**没有注册成工具、没有真实数据源接入**；web provider 明确不抓取 | 数据获取入口 + `pi-research` 授权抓取 + 数据集工具 | 学生报告里「7 国政策矩阵、21 省市表、CR4 95%、120 起投融资」这类**产业事实**，当前仍拿不到 |
| **证据层** | 有 `EvidenceRegistry`（注册/单位/CAGR/分部求和校验）与 `datasetEvidenceItems`，但**业务函数和工具尚未接线** | 把 evidence 注入每个工具 results，统一 `missingEvidence` 汇总 | 无法回答「这个 560 亿是哪个机构、哪一年、什么口径」 |
| **编排层** | 9 个产业工具各自为战 | `run_industry_analysis` 五阶段编排 + session journal | 学生报告是一次完整叙事，当前是一堆独立 JSON |
| **交付层** | 只有 `export_data` 导 CSV/JSON | 没有报告规格（DeckSpec）、没有接入 OpenBuddy 已有的 `ob_pptx/ob_docx/ob_xlsx`、没有版式预览 | 学生报告是 28–36 页带表格和图表；当前输出是 JSON |
| **展示层** | OpenBuddy 只能对 `.pptx` **抽文本**预览；mermaid 可渲染 | 幻灯片版式预览、图表预览、规格驱动预览 | 用户看不到「像一份 PPT」的成品 |

**一句话**：P0 把「计算器」修准了；P1/P2 要把它变成「有数据、有编排、有图、能看能导出」的成稿。**不需要再造分析公式，也不需要新建 PPT 引擎——OpenBuddy 已有 `officegen` 渲染链，只差规格与接线。**

**红线不变**：学生 PPT 本身可信度参差（3D 报告引用「Wohlers Report 2026」却给出 2025 精确区间；生猪报告写「预计 2022 年下半年结束」已过期）。本计划**不追求复刻学生的数字**，只对标其**信息密度与结构完整性**；所有数字必须来自可核验来源或用户显式输入，否则进 `missingEvidence`。

## §5 DeckSpec：报告规格契约（P1/P2 的核心）

> 目标：**分析层只产出数据，渲染层只消费同一份规格**。这样 upup 离线 CLI 与 OpenBuddy 桌面端共用一套版式语义。

### 5.1 规格定义

```ts
export interface DeckSpec {
  schemaVersion: 1;
  title: string;
  subtitle?: string;
  asOf: string;                       // YYYY-MM-DD
  sources: DeckSource[];              // { id, name, url?, asOf }
  slides: DeckSlide[];                // ≤ 100（沿用 officegen 上限）
}

export interface DeckSlide {
  title: string;
  kicker?: string;                    // 顶部小标签：章节名
  layout: 'cover' | 'section' | 'content' | 'comparison' | 'table' | 'chart' | 'kpi';
  blocks: DeckBlock[];
  speakerNotes?: string;
  evidenceIds?: string[];             // 该页数字对应的证据 id
}

export type DeckBlock =
  | { kind: 'bullets'; items: string[] }
  | { kind: 'paragraph'; text: string }
  | { kind: 'table'; headers: string[]; rows: Array<Array<string | number>>; caption?: string }
  | { kind: 'chart'; chartType: 'column' | 'line' | 'pie'; title: string; categories: string[]; series: Array<{ name: string; values: number[] }>; sourceId?: string }
  | { kind: 'kpi'; items: Array<{ label: string; value: string; delta?: string }> }
  | { kind: 'image'; path: string; alt?: string }
  | { kind: 'note'; text: string; tone: 'assumption' | 'inference' | 'disclaimer' }
  | { kind: 'mermaid'; source: string; caption?: string };
```

### 5.2 版式映射（两份 renderer，同一语义）

| DeckBlock | OpenBuddy `buildPptx`（OOXML） | `DeckPreview`（HTML） | 备注 |
|---|---|---|---|
| `bullets`/`paragraph` | `slide.addText`（现状） | `<ul>/<p>` | 已有 |
| `table` | `slide.addTable(rows, opts)` | `<table>` | 新增；列宽按列数自适应 |
| `chart` | `slide.addChart({title, renderType, data})` | 内联 SVG 柱/线/饼 | 新增；officegen 用 `tempDir` 生成临时 xlsx，需指向 `os.tmpdir()` |
| `kpi` | 3 个文本框/形状 | flex 卡片 | 新增 |
| `image` | `slide.addImage` | `<img>` | 新增；仅允许工作区相对路径 |
| `mermaid` | 导出时渲染为图片再 `addImage`（可选） | `MermaidView` | 预览优先；导出降级为 note |
| `note` | 带色块文本 | 带色块 | 事实/假设/推断分节 |

### 5.3 归属与边界

- **upup 侧**：`src/report-spec.ts`（纯函数）`buildIndustryDeck(result) → DeckSpec` + `validateDeckSpec(spec)`。只产出规格，**不写文件、不依赖 officegen**。
- **OpenBuddy 侧**：扩展 `buildPptx` 接受 `blocks`；`ob_pptx` 保留 `slides[].bullets`（向后兼容）并新增 `slides[].blocks`；新增 `DeckPreview` 组件。
- **离线 upup CLI**：P2 可选 `packages/pi-report-export/`，复用同一 `DeckSpec` 与 `officegen` 落盘；不复制布局代码（renderer 函数独立单测，两边用同一组 fixture 快照）。
- **跨仓契约校验**：`DeckSpec` fixture（3D 打印样例）存于 upup `test/fixtures/industry-deck.json`；OpenBuddy 侧用同一文件做快照测试，防止语义漂移。

## §8 风险与合规

1. **数据真实性**：学生 PPT 含过期/无来源数字。**不得为凑密度生成未来年份或无来源数字**，宁可 `missingEvidence` 留空。
2. **合规红线**：不抓数据（除外授权 `pi-research`）、不编数字；风险公式标注；输出条件化区间与置信度；不给单点目标价；不构成交易指令；产业工具**不触碰 toolPolicy**。
3. **跨仓漂移**：upup `DeckSpec` 与 OpenBuddy renderer 必须用同一 fixture 做快照；规格变更走 `schemaVersion`。
4. **officegen 风险**：`addChart` 依赖临时 Excel builder 与 `tempDir`；在 Electron 打包环境中必须显式设 `os.tmpdir()`，并清理临时文件。
5. **依赖风险**：不引入 `pptxgenjs`。若未来确需高级版式，优先评估 `officegen` 的 `createChart`/`addShape`，而非换引擎。
6. **并行仓库风险**：UpUp 仓库有大量他人未提交改动（`bun.lock`、根 `package.json`、各 `packages/*/package.json`）。提交时**只挑本次相关文件**，禁止 `git add -A`。
7. **不虚构展示数据**：预览不得自行补造图表数据；空数据渲染为空态并显示「缺少证据」。
