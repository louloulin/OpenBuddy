## §0 结论先行

**v3 结论**：编排、证据门禁、报告规格、PPTX 导出与版式预览已打通（P1/P2-1/P2-2 完成）。用 3D 打印报告事实真跑一遍：29 页 / 14 表 / 5 图，16 类内容块覆盖 9 类，估值因缺定量输入而如实留空。剩余差距集中在**真实数据获取**与**文字体量**，见 §11。下文 §0 表格保留 v2（P0 后）的判断作为基线。

**（v2）方法论骨架 100%（9/9），输入模型与去伪精确已补齐（P0 完成），数据接入与成稿展示仍是 0。**

现有产业工具已把《产业分析与投资》讲义的分析骨架实现为确定性纯函数：PEST / 市场四维 / 产业链 SCP / 六维趋势 / 五力 / 利润池 / 企业画像 / 利润驱动 / 投资价值，加上已存的 DCF/DDM/可比/期权/技术面工具。P0 又补了数据适配器、证据注册表、扩输入模型与去伪精确。

**剩下的差距全部集中在「最后一公里」**：

| 层 | P0 后现状 | 仍缺 | 对标 6 份 PPTX 的直观结果 |
|---|---|---|---|
| **数据层** | 有 `IndustryDataset` 适配器（inline/json/web 三 provider），但**没有注册成工具、没有真实数据源接入**；web provider 明确不抓取 | 数据获取入口 + `pi-research` 授权抓取 + 数据集工具 | 学生报告里「7 国政策矩阵、21 省市表、CR4 95%、120 起投融资」这类**产业事实**，当前仍拿不到 |
| **证据层** | 有 `EvidenceRegistry`（注册/单位/CAGR/分部求和校验）与 `datasetEvidenceItems`，但**业务函数和工具尚未接线** | 把 evidence 注入每个工具 results，统一 `missingEvidence` 汇总 | 无法回答「这个 560 亿是哪个机构、哪一年、什么口径」 |
| **编排层** | 9 个产业工具各自为战 | `run_industry_analysis` 五阶段编排 + session journal | 学生报告是一次完整叙事，当前是一堆独立 JSON |
| **交付层** | 只有 `export_data` 导 CSV/JSON | 没有报告规格（DeckSpec）、没有接入 OpenBuddy 已有的 `ob_pptx/ob_docx/ob_xlsx`、没有版式预览 | 学生报告是 28–36 页带表格和图表；当前输出是 JSON |
| **展示层** | OpenBuddy 只能对 `.pptx` **抽文本**预览；mermaid 可渲染 | 幻灯片版式预览、图表预览、规格驱动预览 | 用户看不到「像一份 PPT」的成品 |

**一句话**：P0 把「计算器」修准了；P1/P2 要把它变成「有数据、有编排、有图、能看能导出」的成稿。**不需要再造分析公式，也不需要新建 PPT 引擎——OpenBuddy 已有 `officegen` 渲染链，只差规格与接线。**

**红线不变**：学生 PPT 本身可信度参差（3D 报告引用「Wohlers Report 2026」却给出 2025 精确区间；生猪报告写「预计 2022 年下半年结束」已过期）。本计划**不追求复刻学生的数字**，只对标其**信息密度与结构完整性**；所有数字必须来自可核验来源或用户显式输入，否则进 `missingEvidence`。

## §1 基准拆解：6 份 PPTX 到底包含什么

> 提取方式：`unzip -p *.pptx ppt/slides/slide*.xml` 抽 `<a:t>` 文本；手持影像报告为整页图片，逐页读图确认。

### 1.1 六份报告的体量

| 报告 | 页数 | 正文字数 | 类型 |
|---|---:|---:|---|
| `产业分析与投资.pptx`（讲义） | 18 | 968 | 框架方法论，非案例 |
| `3D打印产业分析报告.pptx` | 33 | 11 361 | 产业分析（重政策+市场+链） |
| `氢能产业研究报告(2).pptx` | 36 | 23 660 | 产业分析（重技术路线+单位经济+投融资） |

| `郑凯轩、彭伊宁、陈雅文-生猪行业报告.pptx` | 28 | 11 060 | 产业分析（重政策+周期+财务趋势） |

**体量结论**：合格案例报告 = **28–36 页 × 8 000–24 000 字 × 10+ 张表格/图**。这是验收 rubric 的物理下限。

### 4.4 展示层（用户问的「展示 PPT 的插件」）

| 能力 | 插件/位置 | 现状 | 差距/结论 |
|---|---|---|---|
| 工作台产物预览 | `apps/web/src/features/workbench/ArtifactPreview.tsx:135` | docx/pptx/sheet 交给 `FilePreview` | 可用，但只抽文本 |
| OOXML 文本预览 | `apps/web/src/shared/lib/files/doc-preview.ts:172` `extractPptxFromZip` | ✅ 按 slide 顺序抽 `<a:t>` 文本 | **没有版式、没有图表**；`FilePreview` 只按页列文本 |
| Markdown 渲染 | `@openbuddy/markdown`（`packages/markdown`） | ✅ mermaid/katex/代码高亮 | 报告正文预览直接复用 |
| Mermaid 图 | `apps/web/src/features/workbench/MermaidView.tsx:10` + `mermaid@^11.16.0`（根 `package.json:100`） | ✅ 懒加载、失败回退源码 | **可承载产业链/趋势图** |
| 终端图示 | `@earendil-works/pi-coding-agent@1.6.1` 依赖 `lovely-mermaid@0.3.3`（`bun.lock`） | ✅ Pi TUI 内置 mermaid 渲染 | upup CLI 场景可直接用 |
| 图表库 | 无 echarts/recharts/vega | — | 不引入重型依赖；用 officegen 原生图表 + mermaid/HTML |
| PPT 版式预览 | **无** | — | **P2 新增 `DeckPreview`**：把 `DeckSpec` 渲染成 16:9 HTML 幻灯片，进工作台 |

**展示结论**：当前「展示插件」只解决了**文本可读**，没有解决**版式可见**。最小可行方案是「同一份 `DeckSpec`，一套 HTML 预览 + 一套 OOXML 导出」，而不是上 PowerPoint 转图/截图。

### 4.5 不建议引入

| 候选 | 原因 |
|---|---|
| `pptxgenjs` | 与现有 `officegen` 重复；引入第二个 PPT 引擎要维护两套布局语义 |
| Playwright/LibreOffice 截图转图 | 系统依赖重、打包体积大、CI 不稳定 |
| echarts/recharts | 前端体积大；报告图表数量有限，officegen `addChart` 足够 |

## §5 DeckSpec：报告规格契约（P1/P2 的核心）

> 目标：**分析层只产出数据，渲染层只消费同一份规格**。这样 upup 离线 CLI 与 OpenBuddy 桌面端共用一套版式语义。

### 5.1 规格定义

```ts
export interface DeckSpec {
  schemaVersion: 1;
  title: string;
  subtitle?: string;
  asOf: string;                       // YYYY-MM-DD
  sources: DeckSource[];              // { id, name, url?, asOf }
  slides: DeckSlide[];                // ≤ 100（沿用 officegen 上限）
}

export interface DeckSlide {
  title: string;
  kicker?: string;                    // 顶部小标签：章节名
  layout: 'cover' | 'section' | 'content' | 'comparison' | 'table' | 'chart' | 'kpi';
  blocks: DeckBlock[];
  speakerNotes?: string;
  evidenceIds?: string[];             // 该页数字对应的证据 id
}

export type DeckBlock =
  | { kind: 'bullets'; items: string[] }
  | { kind: 'paragraph'; text: string }
  | { kind: 'table'; headers: string[]; rows: Array<Array<string | number>>; caption?: string }
  | { kind: 'chart'; chartType: 'column' | 'line' | 'pie'; title: string; categories: string[]; series: Array<{ name: string; values: number[] }>; sourceId?: string }
  | { kind: 'kpi'; items: Array<{ label: string; value: string; delta?: string }> }
  | { kind: 'image'; path: string; alt?: string }
  | { kind: 'note'; text: string; tone: 'assumption' | 'inference' | 'disclaimer' }
  | { kind: 'mermaid'; source: string; caption?: string };
```

### 5.2 版式映射（两份 renderer，同一语义）

| DeckBlock | OpenBuddy `buildPptx`（OOXML） | `DeckPreview`（HTML） | 备注 |
|---|---|---|---|
| `bullets`/`paragraph` | `slide.addText`（现状） | `<ul>/<p>` | 已有 |
| `table` | `slide.addTable(rows, opts)` | `<table>` | 新增；列宽按列数自适应 |
| `chart` | `slide.addChart({title, renderType, data})` | 内联 SVG 柱/线/饼 | 新增；officegen 用 `tempDir` 生成临时 xlsx，需指向 `os.tmpdir()` |
| `kpi` | 3 个文本框/形状 | flex 卡片 | 新增 |
| `image` | `slide.addImage` | `<img>` | 新增；仅允许工作区相对路径 |
| `mermaid` | 导出时渲染为图片再 `addImage`（可选） | `MermaidView` | 预览优先；导出降级为 note |
| `note` | 带色块文本 | 带色块 | 事实/假设/推断分节 |

### 5.3 归属与边界

- **upup 侧**：`src/report-spec.ts`（纯函数）`buildIndustryDeck(result) → DeckSpec` + `validateDeckSpec(spec)`。只产出规格，**不写文件、不依赖 officegen**。
- **OpenBuddy 侧**：扩展 `buildPptx` 接受 `blocks`；`ob_pptx` 保留 `slides[].bullets`（向后兼容）并新增 `slides[].blocks`；新增 `DeckPreview` 组件。
- **离线 upup CLI**：P2 可选 `packages/pi-report-export/`，复用同一 `DeckSpec` 与 `officegen` 落盘；不复制布局代码（renderer 函数独立单测，两边用同一组 fixture 快照）。
- **跨仓契约校验**：`DeckSpec` fixture（3D 打印样例）存于 upup `test/fixtures/industry-deck.json`；OpenBuddy 侧用同一文件做快照测试，防止语义漂移。

## §8 风险与合规

1. **数据真实性**：学生 PPT 含过期/无来源数字。**不得为凑密度生成未来年份或无来源数字**，宁可 `missingEvidence` 留空。
2. **合规红线**：不抓数据（除外授权 `pi-research`）、不编数字；风险公式标注；输出条件化区间与置信度；不给单点目标价；不构成交易指令；产业工具**不触碰 toolPolicy**。
3. **跨仓漂移**：upup `DeckSpec` 与 OpenBuddy renderer 必须用同一 fixture 做快照；规格变更走 `schemaVersion`。
4. **officegen 风险**：`addChart` 依赖临时 Excel builder 与 `tempDir`；在 Electron 打包环境中必须显式设 `os.tmpdir()`，并清理临时文件。
5. **依赖风险**：不引入 `pptxgenjs`。若未来确需高级版式，优先评估 `officegen` 的 `createChart`/`addShape`，而非换引擎。
6. **并行仓库风险**：UpUp 仓库有大量他人未提交改动（`bun.lock`、根 `package.json`、各 `packages/*/package.json`）。提交时**只挑本次相关文件**，禁止 `git add -A`。
7. **不虚构展示数据**：预览不得自行补造图表数据；空数据渲染为空态并显示「缺少证据」。

## §11 真实对比：用 3D 打印报告跑通全链路后的问题与优化

> 样例：`upup/packages/pi-investment-analysis/test/fixtures/industry-3d-printing.input.json`，事实全部转引自学生报告并标注「转引未核验」；产出 `industry-deck.json`（同一文件复制到 OpenBuddy `packages/services/test/fixtures/` 做跨仓快照）。

### 11.1 链路结果

| 阶段 | 结果 |
|---|---|
| collect | 政策 7 条、客户细分 6 类、单位经济 2 项、技术路线 2 条、并购 2 起 → 登记证据 2 条（只有数值进注册表） |
| industry | PEST attractive、六维 expanding（90）、五力吸引力 45、SCP 结构分来自真实 CR4 95% |
| company | skipped（3D 报告是产业报告，无单一公司） |
| valuation | 只有定性输入 → 不出区间，结论「缺少估值输入」 |
| review | 三支点答 2/3；`投资价值` 如实为 false |
| 交付 | DeckSpec 29 页通过 `validateDeckSpec`；`ob_pptx` 导出 29 页 `.pptx`、5 个原生图表；`DeckPreview` 可翻页 |

### 11.2 对比中发现并已修复的问题（v3）

| # | 问题 | 修复 |
|---|---|---|
| 1 | 学生报告的「微笑曲线」只有环节毛利率、没有环节收入，利润池算不出，B5 为 0 | `analyzeIndustryChain` 新增 `marginCurve`，自动识别微笑曲线；报告新增「环节毛利率」表与曲线图 |
| 2 | 结构/绩效/利润池在完全无输入时仍按 50 分中性给分（伪精确） | 改为 `null`；SCP 总分只对有值部分取均值 |
| 3 | 市场规模序列混用单位（亿元 vs 元）会静默算错 CAGR | 直接拒绝；序列点缺单位/来源进 `missingEvidence` 并作为阻断级缺口 |
| 4 | 数据集里缺来源的数字以 `unspecified` 占位进入证据 | 来源置空 → 注册表拒收 → 进缺口清单 |
| 5 | 9 个工具的缺证据是字符串数组，编排器无法门禁 | 统一为 `{field, reason}[]`，并写入 `details.missingEvidence` |
| 6 | 无数据时会生成空表空图 | 构建器与两端渲染器均跳过空数据；预览显示「缺少证据」 |
| 7 | officegen 图表临时文件写在 cwd、且打包时同步删除导致 ENOENT/挂起 | 临时目录改到 `os.tmpdir()`；打包期延迟删除；图表回调 15 秒超时报错 |

### 11.3 仍存在的问题（下一步优化，按收益排序）

1. **市场规模与区域规模拿不到**（B2 ✗，市场章节整段缺失）：学生报告这两块是图片（热力图、柱状图），文本抽取不到数字。需要 `pi-research` 授权抓取或用户上传原始数据表 → `industry_dataset_load`。建议 P3-3 扩展为「抓取结果 → 数据集草稿 → 用户确认」流程，而不是让模型读图估数。
2. ✅（v4）**区间值**：`RegionalScaleEntry`/`UnitEconomicsEntry` 增加 `low/high`，校验 `low ≤ value ≤ high`（`invalid-range`），表格显示「29–69」，证据标签带区间。图表误差线、估值传播区间仍未做。
3. 🟡（v4 部分）**文字体量不足**：财务页新增只复述输入与派生值的叙述段（CAGR、净利率变化、扭亏、同口径同比），但两份样例仍 < 4 000 字。确定性层不再继续加字：剩余叙述应由 Agent 基于已登记证据写进 paragraph 或 `speakerNotes`（DeckSpec 已有该字段，`buildPptx` 会写入备注）。原文：≈3 600 字，低于 rubric 6 000 字。差距来自没有「分析叙述」：现在只有表格与评分。建议给每章生成**有来源约束的** speakerNotes / paragraph（只引用已登记证据与模型结论），而不是补数字。
4. ✅（v4）**企业层与财务**：TOP TOY 样例覆盖 B10/B11/B12/B15，见 §12。`pi-finance-sdk.get_financials` 自动取数仍待做。原文：3D 样例没有公司输入。下一步用 TOPTOY 报告做第二个样例，并接 `pi-finance-sdk.get_financials` 自动填 `profitDrivers.financials`（禁用 `knowledge-snapshot.ts` fixture）。
5. ~~B8 覆盖判定偏宽~~ ✅ 已修：B8 现在要求至少一项带货币单位的单位成本，或实际跑过利润模型；3D 样例的两项百分比降幅不再计入（覆盖由 10/16 如实降为 9/16）。
6. **PPTX 折线图降级为柱图**：officegen 只渲染 column/pie。若需要真折线，需在 `officechart` 之上补 `c:lineChart` XML 模板（仍不引入 pptxgenjs）。
7. **mermaid 只在预览可见**：PPTX 导出为说明文字。可选方案：预览端把 mermaid SVG 导出为 PNG 写入工作区，再走 `image` 块。
8. ✅（v4 xlsx）**同源导出**：`deckSpecToXlsx` 把表格（续页合并）、图表数据、来源写成工作表，`ob_xlsx` 接收 `deck`。`.docx` 仍未做。原文：附录证据清单、财务序列应同时导出为 `ob_xlsx`。建议加 `deckSpecToXlsx`（表格块 → sheet）。
9. ✅（v4）**P2-4 rubric**：`evaluateIndustryReport`，见 §6 P2-4。
