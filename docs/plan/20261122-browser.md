## 0. 结论摘要

**判断：OpenBuddy 目前零浏览器自动化，是绿地；但它已具备一块关键拼图 —— `GatewayTransport` + `BridgeFallback` 证明"非 Electron 宿主端到端可用"，而 Chrome MV3 扩展正是一种非 Electron 宿主。**

三个决定性事实（均已核实）：

1. **Pi 插件生态完全够用** —— `pi.registerTool()` 支持 JSON-Schema 参数、`onUpdate` 流式、`signal` 取消、`tool_call` 拦截、`ctx.ui` 审批、图像附件。Chrome 桥**无需任何 Pi 缺失的 API**。（来源：Pi `docs/extensions.md` 3367 行全文）
2. **Hope 的 Chrome 栈是三进程链** —— Chrome 扩展 SW →(Chrome Native Messaging stdio)→ 极薄 relay 二进制 →(unix socket)→ 进程内 broker → 工具层。**核心设计：边缘薄、核心厚** —— 扩展与 relay **永不做安全裁决**，全部策略集中在后端。
3. **OpenBuddy 的 Electron 锁定死了"应用内浏览器"这条路** —— `webviewTag:false` + `will-attach-webview` preventDefault + CSP `frame-src ob-preview:`。所以"真实 Chrome 标签页 / cookie / history / 截图"**只能由真正的扩展提供**，无法在应用内等价实现。

**推荐路线：先 CDP（P1）后扩展（P2），但**架构先按扩展终态设计**（P0 就把协议与安全边界定死），避免返工。

| 阶段 | 内容 | 周期 | 用户可见价值 |
|---|---|---|---|
| **P0** | 契约：协议常量、backend trait、SSRF 门、工具 schema、fake backend + 单测 | 1 周 | 无（地基） |
| **P1** | CDP 后端：隔离 Chrome（复用已有 `playwright-core`） | 2–3 周 | 高：模型能看页面、点按钮、填表、截图 |
| **P2** | Chrome 扩展 + native host：操作用户**已登录**的真实 Chrome | 3–4 周 | 最高：能用自己的身份浏览 |
| **P3** | Chrome UI 交互完善：面板、实时镜像、人工接管、原生控件 | 2 周 | 高：人机协作闭环 |
| **P4** | 生态：MCP server / pi-package 复用 | 1–2 周 | 中 |

### 1.1 Pi 插件生态

来源：`node_modules/@earendil-works/pi-coding-agent/docs/extensions.md`（3367 行，全文）、`docs/rpc-extension-ui.md`（200 行）。

| 能力 | 事实 | 对本计划的意义 |
|---|---|---|
| 入口 | `export default function (pi: ExtensionAPI)`，可 async；jiti 转译，**无构建步骤** | 浏览器桥可直接写成 `.ts` 放进 `packages/engine/src/builtin/` |
| 工具注册 | `pi.registerTool({ name, description, parameters, execute })`；TypeBox → JSON Schema，由 `pi-schema` 校验；参数宽松强制（数字字符串→数字、`"true"`→布尔、标量→数组） | `browser` 工具的 schema 照 Hope 移植即可 |
| 流式/取消 | `execute(toolCallId, params, signal, onUpdate, ctx)`；`onUpdate` 推增量；`signal` 取消 | 页面快照/截图可增量推送；取消直接接用户 Stop |

| 工具注解 | `annotations`：`readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint` | `browser` 标 `openWorldHint` + `destructiveHint`，让审批 UI 有依据 |
| 事件拦截 | `pi.on("tool_call", …)` 可阻断/改写工具调用；`tool_result` / `context` 可塑形 | **审批门落在 `tool_call`**，与 OpenBuddy 现有 `permissions.ts` 对齐 |
| 主动推送 | `sendUserMessage` | 页面侧事件（下载完成、弹窗）可回灌对话 |
| UI 交互 | `ctx.ui.select/confirm/input/editor` + `notify/setStatus/setWidget`；`ctx.ui.custom()` 是 **TUI 组件** | **Pi 的 custom UI 是终端 UI，不适合做浏览器面板** |
| RPC 模式 | `extension_ui_request` / `extension_ui_response`（带 `id`）；对话框类阻塞等待，火警类不等响应 | OpenBuddy 已有等价桥（`packages/engine/src/extension-ui/bridge.ts`） |
| 权限 | "与 Pi 进程同 OS 权限"，扩展可读 prompt / 工具调用 / 文件 / 凭据 / 会话历史 | 浏览器桥只做薄转发，**不要**在扩展侧持有凭据 |
| 导入 | 全部 `node:*` 内建、任意 npm 依赖（需同目录 `package.json`） | 可直接用 `ws`、`node:crypto`、SQLite |

### 1.2 Hope Agent 的 Chrome 栈

来源：`/tmp/hope-agent/crates/ha-browser/`（26 文件 / ~18K 行）、`crates/ha-browser-host/`、`extensions/chrome/`（MV3 扩展）、`docs/architecture/core/browser.md`（575 行）。

**进程拓扑**：

```
模型工具 browser (8 actions)
        │
        ▼
  BrowserBackend trait  ← backend_select.rs（按 action 语义选后端）
        │
        ├── ExtensionBackend ──▶ 用户的真实 Chrome
        │        │  (chrome.debugger = CDP)
        │        ▼
        │   Chrome 扩展 SW (MV3)
        │        │  chrome.runtime.connectNative
        │        ▼
        │   ha-browser-host（极薄 relay 二进制：帧转发，零策略）
        │        │  unix socket / pipe / tcp
        │        ▼
        └── CdpBackend ──────▶ 隔离托管 Chrome（chromiumoxide，裸 CDP）
                 │
                 ▼
          Core broker（策略：连接仲裁、tab lease、blob 校验、session 清理）
```

**协议常量（移植时逐条照抄）**：

```
PROTOCOL_VERSION = 1
帧头                  = u32 LE + JSON
MAX_NATIVE_MESSAGE_LEN = 1 MiB      MAX_BROKER_MESSAGE_LEN = 1 MiB
MAX_DIRECT_RESPONSE_BYTES = 768 KiB  RESPONSE_BLOB_CHUNK_BYTES = 192 KiB
MAX_CHUNKED_RESPONSE_LEN = 64 MiB / 512 chunk / TTL 10 min
MAX_BLOB_SIZE = 256 MiB / 4096 chunk / TTL 10 min
CALL_TIMEOUT = 15 s
```

**安全门**：
- SSRF 检查覆盖 `navigate.go` / `tabs.new` / `profile.connect`（防模型拨任意远端 9222）/ `control.evaluate`（正则扫描脚本里的 URL 字面量，`HTTP://` 大写也拦）/ `control.raw_cdp` 的 `Page.navigate` 与 `Runtime.evaluate`
- `control.raw_cdp` 额外 **4 道独立门**（配置开关 + 后端类型 + 扩展托管 + 方法白名单）—— **四道门齐了才能发布 raw_cdp**
- 审批理由与受保护路径在 Core，`SSRF` 在 base 层，**扩展与 relay 永不做裁决**

**三条必须逐字抄的设计决策**（Hope 的注释原话）：

> 1. host **必须**在失去 broker 时死掉；"更健壮的 host"才是 bug。
> 2. `ExtensionRequired` **必须** fail-closed —— 在隔离 profile 里"成功"比失败更糟。
> 3. `fill` **必须**走原型 setter 写入并派发 `input`+`change`，否则所有框架受控表单会静默拒绝 agent 输入。

## 2. 架构决策

### 决策 1：边缘薄、核心厚

扩展 SW 与 relay 二进制**只做转发，不持有任何策略**。所有裁决（后端选择、tab 归属、SSRF、审批、blob 校验）在 OpenBuddy Core。

**理由**：Hope 的核心洞见。边缘做裁决 = 策略散落、无法统一审计、绕过即失守。

### 决策 2：接缝选 A（扩展作为远程客户端），保留 B 作为补充

| 接缝 | 做法 | 成本 | 能拿到什么 | 不能拿到 |
|---|---|---|---|---|
| **A. 扩展作为远程客户端** ✅ 推荐 | 扩展 MV3 SW 用 `GatewayTransport`（fetch + SSE，已验证 MV3-safe）连 `127.0.0.1`，复用 `host_capabilities` 能力协商 | **最低** | 真实标签页 / cookie / history / 截图 / 真实前进后退 | 需桌面端新增 loopback 监听 + 放行 `chrome-extension://` origin |
| **B. 扩展作为 Pi 工具提供者** | 发布 `pi-package`，桌面端直接获得网页能力，零 Chrome API | 中 | fetch/read | **不是 Chrome 扩展栈**；拿不到标签页/cookie |
| **C. Pi 内建 WS 服务器** | 在 `ob_browser` 内建扩展里起 WS server | 中 | 可控性最好 | 只活于 Pi session 期间；与已有 Gateway 体系重复 |

**结论**：主路走 **A**（复用已验证的 `GatewayTransport` 端到端链路），同时把 **P1 的 CDP 后端**做成 B/C 之外的第三条 —— 因为它不需要用户装任何东西。

### 决策 3：先 CDP，后扩展，但**契约先定**

CDP 后端（P1）**不依赖用户装扩展**，能独立交付真实价值；扩展（P2）受制于 Chrome 商店审核与用户安装意愿，节奏不可控。

但**协议帧格式、常量、安全门、backend trait、tool schema 在 P0 就按扩展终态定义**，P1/P2 只是换 backend 实现。

### 决策 4：UI 面板是 OpenBuddy 的一等 React 面，不是 Pi TUI

Pi 的 `ctx.ui.custom()` 是**终端组件**，做不了浏览器视图。OpenBuddy 已有 `packages/engine/src/extension-ui/bridge.ts` 的 React 桥，但那里只有 select/confirm/input 几类对话框 —— **浏览器面板必须新开一个 React feature surface**，由 OpenBuddy 自己的 transport 驱动，与 Pi 扩展通过协议事件对接。

### 决策 5：把"Chrome UI 交互"当独立能力域对待

Hope 的工具面覆盖了 DOM 交互，但**没有覆盖 OS 级原生控件**（Chrome 的文件选择器、原生下拉、右键菜单、扩展弹窗）。这正是用户要求的"完善整个 chrome ui 交互"里 Hope 自己也缺的部分 —— 本计划要显式补上（见 §6.4）。

## 4. 协议与常量（P0 冻结）

### 4.1 帧格式

```
┌──────────────┬──────────────────────────────┐
│ u32 LE 长度   │ JSON payload (UTF-8)          │
└──────────────┴──────────────────────────────┘
```

- `MAX_NATIVE_MESSAGE_LEN = 1 MiB`；超限直接断链（不截断）
- 二进制（PDF / 截图）**永远走 blob 通道**，不允许内联进 JSON
- blob：`MAX_BLOB_SIZE = 256 MiB / 4096 chunk / TTL 10 min`，整块 sha256 + 原子改名

### 4.2 握手与连接仲裁

```
扩展 → Core:  hello  { extension, extensionVersion, protocolVersion, token }
Core → 扩展:  ok    { protocolVersion, sessionId }
```

- 每次 accept 铸 `connection_id`（`connection_seq` 从 1 起）
- 新 `hello` 到来而旧连接仍活跃 → Core 记 `Superseding…`，**立即 fail_all_pending()**（清空 pending oneshot + chunk 装配），旧的在途调用立刻返回
- disconnect 时**仅当本连接仍是 active 才清状态**（`was_active` 守卫）—— 被 supersede 的旧连接不得动新连接的状态
- token 校验失败 → 拒绝连接，**不回复**
- `request_seq` 从 1 起；每次 `call()` 有 15s 超时，超时后完成的响应无 waiter，直接丢弃

**扩展侧的两个消息入口（必须分开实现）**：

| 入口 | 处理 | 回复 |
|---|---|---|
| `chrome.runtime.onMessage` | `handleExtensionMessage`（async，`return true`） | `{ok:true, result}` / `{ok:false, error:{message, stack}}` |
| native port `onMessage` | `handleHostCommand` → `handleCommand(method, params)` | `{id, ok, result\|error}` |

> **`hello` 由 SW 本地应答，不回环到 native host** —— 否则每次握手都会多一跳 native 帧，且 host 未起时扩展会误判自己离线。

### 4.3 tab 投影形状

扩展把 `chrome.tabs.Tab` 投影为**可跨边界传输的普通对象**（`tabToPlain`），只保留必要字段：

```ts
{ id, windowId, active, audible, discarded, favIconUrl, groupId,
  highlighted, incognito, index, pinned, status, title, url }
```

不做投影的后果：`chrome.tabs.Tab` 含不可序列化的内部句柄，且会把无关字段带过信任边界。

### 4.4 二进制与 blob

- 二进制（PDF / 截图）**永远走 blob 通道**，不允许内联进 JSON
- blob：`MAX_BLOB_SIZE = 256 MiB / 4096 chunk / TTL 10 min`，整块 sha256 + 原子改名
- blob 标识形如 `pdf-<ts>-<n>` / `screenshot-<ts>-<n>`
- 分块大小 `RESPONSE_BLOB_CHUNK_BYTES = 192 KiB`；直传上限 `MAX_DIRECT_RESPONSE_BYTES = 768 KiB`，超过即转 blob

### 4.5 常量单源

协议常量必须**在 TypeScript 里定义一次**，扩展侧通过构建脚本从同一文件生成（或用 JSON 共享 + 校验测试），**禁止两处手写**。

## 5. 工具面设计（P0 冻结）

### 5.1 单工具八动作

一个 `browser` 工具，8 个 action —— 刻意不拆成多个工具：模型需要"看一眼→决定"的循环，拆开会让每步都变成一次工具选择。

| action | 子操作 | 关键参数 |
|---|---|---|
| `status` | — | — |
| `profile` | `launch` / `connect` / `disconnect` / `install_runtime` | `target`（`managed`/`user_attach`）、`executable_path` |
| `tabs` | `query` / `new` / `activate` / `close` / `finalize` / `claim` | `tab_id`、`url`、`keep[]` |
| `navigate` | `go` / `back` / `forward` / `reload` | `url` |
| `snapshot` | — | `interactive`、`compact`、`screenshot`、`annotate`、`image_format`、`ref` |
| `act` | `click` / `dblclick` / `fill` / `select` / `hover` / `press` / `scroll` / `drag` / `upload` | `ref`、`text`、`value`、`option` |
| `control` | `evaluate` / `raw_cdp` | `script`、`method`、`params` |
| `download` | `cancel` | `download_id` |

### 5.2 工具契约（Pi 侧）

```ts
// packages/engine/src/builtin/browser.ts
export const browserBuiltin: ExtensionFactory = (pi) => {
  pi.registerTool({
    name: "ob_browser",
    description: "驱动浏览器：查看页面结构、点击/填写/选择/上传、截图、下载、导航。",
    parameters: {
      type: "object",
      additionalProperties: false,
      required: ["action"],
      properties: { action: { type: "string" }, /* … */ },
    },
    annotations: { openWorldHint: true, destructiveHint: true, readOnlyHint: false },
    // 与 Hope 一致：默认不进 system prompt，靠 tool_search 拉取
    defaultActive: false,
    async execute(_id, params, signal, onUpdate, ctx) { /* … */ },
  });
};
```

**必须复刻的参数解析坑（Hope 已踩）**：

1. **两个 `get_str` 访问器**：`get_str` 把 `""` 当缺失，`get_str_any` 保留 `""`。合并二者会静默弄坏 `act.fill text=""`。
2. **空串当缺失**：`url` / `profile` / `executable_path` 的 `""` 必须当缺失，否则 `""` 会传到启动器变成 `No such file or directory`。
3. **参数宽松强制**是 Pi 侧行为（数字字符串等），但我们**不要依赖**它做业务判断。

### 5.3 动作语义与"Chrome UI 交互"完整清单

| 动作 | 语义 | 关键正确性要求 |
|---|---|---|
| `click` | 命中元素中心，真实鼠标事件 | 需先 scrollIntoView；元素被遮挡时先报遮挡而非盲点 |
| `dblclick` | 双击（**旧别名 `double_click` 需保留兼容**） | — |
| `fill` | 清空 + 写入 + 提交 | **走原型 setter + 派发 `input` + `change`**（框架受控表单否则静默失败）；React 需额外派发 `input` 的原生 setter |
| `select` | 原生 `<select>` | 兼容自定义下拉（非 `select` 元素）→ 走"点击展开 + 点选项" |
| `hover` | 触发 hover 态 | — |
| `press` | 键盘 | 支持组合键（`Meta+A`）；**需处理原生快捷键拦截** |
| `scroll` | 滚动容器 | 优先滚内层可滚容器，而非整页 |
| `drag` | 拖拽 | HTML5 DnD 与指针事件两条路径 |
| `upload` | 上传文件 | **原生文件选择器是 OS 级窗口，DOM 不可达** → 见 §6.4 |
| `screenshot` | 截图 | 面板用 JPEG q70；工具侧尊重 `image_format` / `annotate` / `ref` 裁剪 |
| `download` | 下载/取消 | 下载文件**原地不搬移**，回报原始路径让 agent 就地读 |

### 5.4 参数别名与兼容表（兼容包袱，逐条保留）

模型会自由变换参数名。下列别名与降级规则**必须**接受，否则会出现“模型传了合法参数但工具不认”的静默失败：

| 规范名 | 接受的别名 | 说明 |
|---|---|---|
| `target_id` | `page_id` | 标签页标识 |
| `download_id` | `downloadId` / `id` | 三种拼写 |
| `expression` | `script` | `control.evaluate` 的脚本 |
| `annotate` | `annotated` | 截图标注开关 |
| act kind `fill` | `type` | 旧名 |
| act kind `dblclick` | `double_click` | 旧名 |
| snapshot `role` | `aria` | 无障碍角色 |
| snapshot `screenshot` | `image` | 截图开关 |
| observe `page_errors` | `errors` | 页面错误 |
| observe `downloads` | `download` | 下载事件 |

**其他两条兼容规则**：
- **嵌套参数回退**：若参数是 `{"text": …}` 形式，取内层 `text`
- **`profile.op=launch` 拒绝旧 `target` 字段**：返回一个**带迁移提示的错误**（指向 `profile=managed|user_attach`），而不是默默忽略

### 5.5 快照落地分级（grounding tiers）

```
DOM 层（快、覆盖广）
  ↓ 不足时
AX 树增强（角色/名称/焦点态）
  ↓ 仍不足时
chrome.scripting 跨源 frame 桥（DOM 启发式）
  ↓ 仍不足时
AX-only（无 DOM 节点）
  ↓ 仍不足时
flat sessions（Target.setAutoAttach flatten，真实 AX + frame 树）
```

**locator 类型**（对模型保持不透明，模型只看到 `[ref=12]`）：
`>>>` / `ax_backend_dom_node_id:` / `frame_ax_backend_dom_node_id:` / `frame:`

**ref 生命周期**：ref 属于 (scope, 当前活动 tab, 最近一次 snapshot)。导航、切 tab、SPA 路由变化、弹窗打开 → **全部失效**。

## 6. 详细设计

### 6.1 后端选择矩阵（fail-closed 是硬要求）

三档需求 × 三档偏好：

| 需求 | 含义 | `extension_first`（默认） | `extension_only` | `cdp_only` |
|---|---|---|---|---|
| `ExtensionRequired` | 需要用户的已登录标签页 | 扩展不可用 → **fail-closed**，返回安装提示 | 同左 | 拒绝（除非该动作本身是 CDP 生命周期） |
| `ExtensionPreferred` | 一般浏览 | 降级到 CDP，结果标 `backend=cdp` | **fail-closed**，不退 CDP | 走 CDP |
| `CdpAllowed` | CDP 生命周期 / Docker / headless | 直接 CDP | 直接 CDP | 直接 CDP |

**规则**：
- **绝不悄悄退回隔离 profile**。用户说"我的 Chrome"，在错误浏览器里"成功"比失败更糟。
- 缓存的后端若 `is_alive()` 报死、或不满足当前需求（如缓存的是 CDP 但这次要 `ExtensionRequired`）→ 丢弃重建。
- 反向：扩展从不可用变可用时，**主动丢弃缓存的 CDP 后端**。
- **只缓存 CDP 后端**；`ExtensionBackend` 携带 session scope，缓存会把一个 session 的 tab 归属泄漏到另一个 session。

### 6.2 SSRF 门（单一 chokepoint）

| 入口 | 检查对象 |
|---|---|
| `navigate.go` | `url` |
| `tabs.new` | `url`（`about:blank` 跳过） |
| `profile.connect` | CDP endpoint URL（防模型拨任意远端 9222） |
| `control.evaluate` | **正则扫描脚本内 URL 字面量**，任一被拒则**整个调用拒绝** |
| `control.raw_cdp` + `Page.navigate` | `params.url` |
| `control.raw_cdp` + `Runtime.evaluate`/`callFunctionOn` | `params.expression` / `functionDeclaration`，同样扫描 |

正则：`(?i)["'\`](https?://[^"'\`\s]+)["'\`]` —— 快路径与正则**都大小写不敏感**，`HTTP://` 不能绕过。

**必须写进文档的已知盲区**（不要假装没有）：动态拼接、base64 编码 URL、`window.location.host`。

### 6.3 `control.raw_cdp` 的四道独立门

四道**全部**就位才允许发布 `raw_cdp`：

1. 配置开关（`browser.extension.allowRawCdp`，默认关）
2. 后端类型必须是扩展后端（CDP 后端不走 raw_cdp）
3. 扩展必须托管该 tab
4. 方法白名单（`validate_raw_cdp_method`）

**并且永不提供 "don't ask again"** —— raw_cdp 每次都要审批。

### 6.4 Chrome UI 交互的完整域（Hope 也缺的部分）

这一节是"**完善整个 chrome ui 交互**"的核心。Hope 的 8 动作覆盖了 DOM 层，但下列 OS 级 / 浏览器级交互要么缺失、要么只有半成品：

| 交互 | 现状 | 本计划要做 |
|---|---|---|
| **原生文件选择器** | OS 级窗口，DOM 完全不可达 —— CDP 无法点击 | 走 `chrome.debugger` + `Page.setInterceptFileChooserDialog`（CDP 有此能力）拦截 chooser 事件；或用 `DOM.setFileInputFiles` 直接给 `<input type=file>` 喂文件（**优先，零 UI 交互**） |
| **原生下拉 / `<select>` 阴影 DOM** | 部分浏览器用 OS 渲染 | `DOM.setFileInputFiles` 同理；对 `<select>` 用 `Runtime.evaluate` 直接设 value + 派发 `change` 作为降级 |
| **浏览器原生弹窗**（`alert`/`confirm`/`prompt`） | CDP `Page.javascriptDialogOpening` 事件 | **必须处理** —— 否则 agent 的一次 `alert` 会永久挂死页面。策略：自动接受 `alert`、把 `confirm` 转成宿主审批 |
| **下载遮罩 / "保存为" 对话框** | OS 级 | CDP `Browser.setDownloadBehavior`（`behavior: 'allow'` + `downloadPath`）直接落盘，绕过对话框 |
| **新标签页 / 弹窗窗口** | `Target.attachedToTarget`（新 window target） | flat session 已覆盖 target 树，但需把**新 window** 纳入 tab 列表并正确归属 |
| **扩展弹窗页面**（`chrome-extension://`） | 无法注入 | 明确列为**不支持**，fail-closed 返回原因 |
| **chrome:// 页面** | 受限页面，CDP attach 受限 | 明确列为**不支持**，给出用户可读原因 |
| **iframe 跨源** | 需 flat session 或 script 注入 | 两级降级（先 flat session，失败退 `chrome.scripting` DOM 桥） |
| **虚拟滚动 / 懒加载** | snapshot 时元素不在 DOM | 滚动后重取；snapshot 支持 `scroll` 参数 |
| **Shadow DOM** | 查询需穿透 | snapshot 时递归穿透 open shadow root，闭包 shadow 标注不可达 |
| **右键菜单 / 浏览器 UI 栏** | DOM 不可达 | 明确**不支持**（不做 OS 级自动化） |
| **触摸 / 移动视口** | 视口不同 | CDP `Emulation.setDeviceMetricsOverride` 支持 |
| **弹窗遮挡（overlay）** | 点击被遮挡 | 点击前做 hit-test，遮挡则报告而非盲点 |
| **剪贴板** | 需权限 | `navigator.clipboard` + 扩展权限；降级为不依赖剪贴板 |

### 6.5 面板与实时镜像

**组件树**（对齐 Hope 的结构，落到 OpenBuddy 路径）：

```
apps/web/src/features/browser/
├─ BrowserPanel.tsx          停靠面板 / 浮动 / 独立窗 三形态
├─ BrowserPanelHost.tsx      三形态共享壳（挂载/卸载/可见性策略）
├─ BrowserPanelContent.tsx   variant=docked / variant=floating
│   ├─ ControlPanelHeader.tsx   后端徽标（extension / cdp / 无）
│   ├─ UrlStrip.tsx             URL 条
│   ├─ FramePreview.tsx         实时帧（aspect-ratio，max-h-55%）
│   ├─ BrowserQuickBar.tsx      后退 / 刷新 / 前往 / 接管暂停 / 外部打开
│   ├─ PanelSessionStats.tsx    会话统计
│   └─ PanelActionTimeline.tsx  动作时间线
├─ frame-store.ts            1 Hz 镜像 + 引用计数 + seq 防乱序
├─ useBrowserFrame.ts        消费 frame-store（useSyncExternalStore）
├─ usePanelActionHistory.ts  动作历史（种子 + 追加 + 缩略图回填）
├─ useReplaySelection.ts     只允许选中有缩略图的行
├─ SnapshotView.tsx          快照渲染 + ref 标注 + 点击回填
├─ TakeoverBar.tsx           人工接管 / 交还
├─ ApprovalCard.tsx          高危动作审批（含 raw_cdp 理由）
├─ TabStrip.tsx              标签页列表 + 归属标记（agent-owned / user-owned）
└─ __tests__/                状态机与 store 不变量测试
```

**形态差异**：`variant=floating` **只渲染 `FramePreview`**（浮动窗就是一块屏幕）；`variant=docked` 才有完整控制区。

**FramePreview 的两条硬规则**：
- 固定 `aspect-ratio`，高度上限 `max-h-55%`（不把整个右栏吃掉）
- **error 优先于 stale frame** —— 一旦出错，**不能继续展示旧帧**（否则用户会以为页面还活着）

**frame-store 不变量（Hope 已验证，逐条照抄）**：
- 每个 store **只有一个** transport 监听 + **一个** 1 Hz 轮询，无论挂了多少容器
- `subscribe`：取消挂起的 detach → 挂监听 → 加入 listeners → 同步定时器
- `unsubscribe`：移除；listeners 归零后 **延迟 300ms 再 detach**（docked↔floating 互换时不掉流）
- 轮询条件：`listeners.size > 0 && pollVotes.size > 0`；投票按容器 key（`"docked"` / `"floating"`）计，任一容器可维持存活
- `refresh()`：单调 `refreshSeq`；**过期 seq 的响应丢弃**
- 采集在途时跳过本次轮询（否则慢后端上每个请求都被顶掉）
- `publish()`：frame / error / displayId 三者皆未变则**不通知**（`useSyncExternalStore` 的 identity 保证）

**面板生命周期**（Hope 已验证）：
- **首次帧自动打开**：活动 session 的第一帧到达时自动展开
- `dismissedRef` 记住用户手动关过 → **不再自动弹出**（否则每次操作都抢注意力）
- 右栏**独占**：与文件浏览器互斥
- 浮动与停靠**共享同一条帧流**（不是两份采集）
- **切换 session 时关闭浮动窗**（否则会拿着 A 的帧显示 B 的上下文）

**动作历史**（`usePanelActionHistory`）：
- 先用 `tool_recent_actions` **种子**，再追加 `browser:action` 事件
- 缩略图从 `browser:frame` 的 `actionId` **回填**（canvas 降采样）
- 合并 → 去重 → 排序；本地缩略图上限 50 张
- `useReplaySelection` **只允许选中有缩略图的行**（无图重放无意义）

### 6.6 人工接管（Human-in-the-loop）

Hope 的做法：扩展在页面上叠加一个**带 Stop 按钮的 overlay**，用户可以随时夺回控制。

OpenBuddy 的落点：
- **应用内**：面板顶部的 `TakeoverBar` —— "我来操作" 切换为人工模式，agent 的动作在人工模式下**被拒**（不是排队）
- **页面内**：扩展注入一个轻量 overlay，显示"OpenBuddy 正在操作此页面"+ Stop 按钮
- **Stop 必须真的停**：Stop 围栏要能中断 CDP 调用与等待中的动作，不能只是 UI 状态

### 6.7 扩展 manifest（权限逐条带理由）

MV3，`minimum_chrome_version: 116`，`default_locale: en`，background 为 `service_worker.js`（`type: module`）。

| 权限 / 声明 | 用途（每条都是承载性的，去掉则功能缺失） |
|---|---|
| `debugger` | CDP attach / sendCommand / sessions —— **整个控制面** |
| `tabs` | `tabs.query/create/update/remove`、tab id、标题 |
| `scripting` | overlay 注入、`frames.snapshot`（`allFrames`）、`frames.act`（`frameIds`） |
| `webNavigation` | `getAllFrames` → frame 树，以及 flat-session ↔ frame 匹配 |
| `downloads` | 下载流观测 + `downloads.cancel` |
| `alarms` | 30s native-port keepalive（**MV3 驱逐后复活端口**） |
| `activeTab` | popup 里“停止当前标签页” —— 不需宽授权 |
| `nativeMessaging` | 端口本身 |
| `host_permissions: http://*/*, https://*/*` | `chrome.debugger` attach + 任意源上的脚本注入 |

**权限最小化策略**：先只申请 `activeTab` + 必要项；`debugger` 与通配 `host_permissions` 作为**用户显式开启后**的升级，而不是安装即要（见风险 B1 / B7）。

### 6.8 CDP 后端的启动序列（逐条照抄，顺序有依赖）

```
熔断器检查
  → 解析可执行文件：override → 平台默认 Chrome → 缓存的 runtime 路径
     （全失败 → 报错并同时发 browser:runtime_required 事件）
  → managed 模式：**每次启动前清空 user-data-dir**
  → create_dir_all
  → 清理陈旧的 SingletonLock
  → spawn 子进程（**保留 child handle**，供 disconnect / Drop 杀进程）
  → 轮询 GET /json/version
  → connect(ws)
```

**关键约束**：
- connect 失败 → **杀掉子进程**，否则它会“霸占” user-data-dir 的 SingletonLock，导致下次启动失败。
- `disconnect` / `launch` 的清理判据是 **`needsCleanup()` 而非 `isConnected()`** —— 死掉的 WebSocket + 活着的 Chrome 进程仍持有 SingletonLock，必须被回收。
- 熔断器：连续启动失败达阈值后拒绝再试，并给出可读原因（否则用户会反复看到 Chrome 闪一下就没）。

### 6.9 帧发射策略与时间线录制（旁路通道，易漏）

**帧发射策略必须集中在一个 choke point**（不能散落到各 action）：

| 动作 | 何时发帧 |
|---|---|
| `act` | **总是发 —— 即使失败也发**（失败瞬间的页面往往最关键） |
| `navigate` | 仅成功时 |
| `tabs.new` / `tabs.select` / `tabs.claim` | 仅成功时 |

**帧负载**：`browser:frame` = `{sessionId, targetId, url, title, jpegBase64, capturedAt, backend, actionId?}`，JPEG **q70**。

- `capture` 在无后端时返回 **null** → 面板显示空状态
- **绝不强制拉起 Chrome**（用户没开浏览器时不该被弹窗）

**时间线录制上限与脱敏**（内存态，不落盘）：

| 项 | 上限 |
|---|---|
| 记录数 | 200 条 / session |
| 缩略图 | 50 张 / session，≤240px，**q60** |
| session 键 LRU | 64 |

**脱敏规则**：
- `fill` 填入的文本**只记 `text(N chars)`**，绝不记内容
- 错误信息**裁剪到 256 字节**
- 观测 ring：console / page errors / network 各 500 条，`since` **严格大于**

### 6.10 全局操作互斥（一个守卫贯穿全流程）

**所有**触及浏览器的操作必须持有**同一个全局 CDP 操作互斥锁**，且覆盖**整个工作流**（从后端选择到动作完成）：

```
browser 工具调用（全部 action）
+ browser_capture_frame（帧采集）
+ panel_navigate（面板导航）
+ browser_launch / connect / disconnect
+ 产物截图采集
```

**锁的跨度必须包含后端选择本身** —— 否则会出现“选后端时 A 进程退出、切到 B 后端，但本次调用仍按 A 的语义执行”的竞态。

> Hoping 的实现：`acquire_cdp_operation_guard()`。CDP 后端**必须**串行化；扩展后端路径不被该锁串行（扩展本身有自己的会话模型），但**后端选择阶段仍需持锁**。

### 6.11 审批与可观测

- 审批理由必须结构化（`action` / `目标 tab` / `目标 URL` / `是否写操作` / `是否离开当前域`），让用户一眼能判
- 观测三通道：console（500 条 ring）、page errors（500 条 ring）、network（500 条 ring）
- `observe` 的 `since` 语义是**严格大于**
- 脱敏：日志**只记 `text(N chars)`，绝不记填入的文本**；错误裁剪到 256 字节；缩略图每 session ≤50 / 总记录 ≤200
- `tool_metadata` 必须小：`browser_activity` 不带 payload

### 7.3 权限引擎的两处必改（易漏）

`packages/engine/src/permissions/permissions.ts` 是审批规则匹配的唯一入口。浏览器工具接进来后，它有两处**必须改**，否则会出现两种具体故障：

**(a) `subject()`（:80）取不到 `url`**

```ts
// 现状：bash 取 command，其余取 path ?? pattern，否则整个 input 序列化
const field = toolName === "bash" ? value.command : value.path ?? value.pattern;
return typeof field === "string" ? field : JSON.stringify(input ?? "");
```

对浏览器工具，上式会退化成 `JSON.stringify(input)` —— 整个参数包。后果：权限规则**无法按 URL 匹配**（`navigate.go` / `tabs.new` / `control.raw_cdp` 的目标域），而 URL 正是浏览器场景里最需要管控的维度。

→ 改为把 `url` 纳入 subject 链（`value.url ?? value.path ?? …`），并对 `browser` 工具单独定义 subject 取值。

**(b) `READ_ONLY`（:72）是写死的四项**

```ts
const READ_ONLY = ["read", "grep", "find", "ls"];
```

浏览器工具没有同名项，于是 `browser_status` / `browser_snapshot` / `browser_tabs_query` 这类**纯读动作在 `auto` 模式下也要弹审批** —— 既吵又把审批面稀释到失去意义。

→ 新增一组只读浏览器动作白名单（如 `["browser_status", "browser_snapshot", "browser_tabs_query", "browser_observe"]`），并保持**写动作**（`act` / `navigate` / `control` / `download`）不在其中。

> 这两处是 Pi 扩展之外的**唯一必需改动**（其余全部在新建的 `packages/engine/src/browser/` 内）。

### 7.4 传输层 Tauri ⇄ HTTP 对等（两条路必须完全等价）

OpenBuddy 的 UI 通过 `packages/client` 的 transport 抽象访问后端。浏览器能力的每条命令都**必须有 Tauri 与 HTTP 两个实现**，且行为一致 —— 否则桌面可用而手机/H5 不可用。

| 命令 | Tauri | HTTP |
|---|---|---|
| `browser_capture_frame` | `browser_capture_frame` | `POST /api/browser/capture-frame` `{sessionId}` |
| `browser_panel_navigate` | `browser_panel_navigate` | `POST /api/browser/panel-navigate` `{op, url, sessionId}` |
| 动作历史 | `tool_recent_actions` | `GET /api/tool-actions` |
| 其余 | `browser_status` / `extension-status` / `profiles` / `launch` / `connect` / `disconnect` / `doctor` / `spawn-user-chrome` / `config` / `install-chromium-runtime` | 同名分组 |

**两个必须写进测试的坑**：

1. **`browser_set_config` 必须调 `resetBackend()`** —— 改完配置不重置后端，新配置不生效（旧后端实例仍在跑）。
2. **`set_config` 的 body 必须包成 `{config: {…}}`** —— 直接传平铺对象会被**强制归一为全默认值**（静默丢配置）。

> 坑 2 是典型的“参数形状错了但没报错”型故障：配置全部回默认值，用户会以为设置没保存。必须有单测锁住请求体形状。

## 11. 明确不做

| 不做 | 理由 |
|---|---|
| 应用内嵌浏览器（`<webview>`） | `webviewTag:false` + `will-attach-webview` 拦截 + CSP `frame-src` 仅 `ob-preview:` —— 是**刻意的安全设计**，不为浏览器功能放宽 |
| 复制 Chrome 商店原生权限组合的"全能扩展" | 权限最小化；先 `activeTab` 再升级 |
| OS 级 UI 自动化（右键菜单、浏览器工具栏、扩展弹窗） | 跨平台不可靠、风险高；显式列为不支持 |
| 网络拦截（`Fetch.*`） | Chrome 域策略风险；`control.raw_cdp` 已受四道门限制 |
| 坐标/视觉 grounding（截图找按钮） | 精度与可解释性差；用 AX/DOM ref |
| 录制回放（record → replay） | 维护成本高，且与真实登录态绑定 |
| 复用 `npx @playwright/mcp@latest` 作为主路径 | 外部进程、版本不可控、无 UI 集成；改为内置实现 |
