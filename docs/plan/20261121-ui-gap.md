# 20261121-ui-gap — UI 对标差距分析、计划与本轮实现

> **日期**：2026-11-21
> **基线**：`main`，工作区另有并行生成物（图标脚本、文档、README、移动端修改）；本轮只改 UI 对标相关文件。
> **对标对象**：WorkBuddy 5.11.3（本机 `WORKBUDDY_UI_REFERENCE.md`、`docs/plan/20261119.md` §10.1 抽样）、Grok Bot 桌面版视觉层（`apps/web/src/styles/grok.css`）、OpenBuddy 当前 `apps/web/src`。
> **说明**：`docs/` 在 `.gitignore` 中，本文需要 `git add -f` 才会入库。

---

## §0 结论先行

OpenBuddy 的 UI 已经不是“缺页面”，而是“缺若干状态细节”：对话、审批、产物工作台、设置、令牌与 Grok Bot 视觉层都已覆盖；本轮关闭了三个可本地验证的真实缺口：

1. **侧栏置顶/分区/空间折叠状态刷新后丢失**（WorkBuddy 明确要求分区状态持久化）。
2. **首页没有首次使用引导**（未配置模型时用户不知道下一步）。
3. **任务概览看不到后台命令终端输出**（WorkBuddy 有独立终端输出模块；OpenBuddy 之前只在回合内显示）。

本轮同时修复了一个**与 UI 无关但阻塞全量测试**的时间边界 flake（`startsInLabel` 测试在整分钟边界被 `Math.floor` 判为 N-1）。未触碰产物云分享 ACL、项目配额守卫、移动端原生等需要服务端契约或新后端能力的项。

## §4 风险与下一步

1. **多窗口同步**：`storage` 事件只在同一浏览器的同源窗口触发；不同 profile 目录不共享，这是预期边界。
2. **折叠态容量**：最多记录 100 个工作空间节点，超出淘汰最早项；避免 localStorage 无限增长。
3. **命令输出截断**：任务概览只展示最近 5 条、每条末尾 4000 字符；完整输出仍在工具详情中可另存，避免弹层挂载大段文本。
4. **首页引导**：按当前会话显示，不写入偏好；如果用户一直未配置模型，下次启动会再次出现。后续如产品要求“不再提示”，再加显式偏好键。
5. 删除的 12 个未挂载 WIP 文件均经 `grep` 确认无生产引用，且 `docs/plan/20261115.md:696` 已列为待删除项；如未来需要恢复可从 git 历史取回。

## §5 下一批建议

产物云分享/ACL（C2）、项目配额守卫（C 线）、业务面板 i18n、原生移动端跟改；均需服务端契约或独立验收，不建议塞进本轮。
