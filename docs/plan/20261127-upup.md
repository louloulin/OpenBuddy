## §0 结论先行

1. **OpenBuddy 自己是默认应用**：`apps_list` 永远返回内置 `openbuddy`（`source:"builtin"`，通用助手，3 个通用场景），排第一并默认选中；内置应用保留原有「日常办公 / 代码开发 / 设计创意」模式 tab，第三方应用才用它的场景行替换。
2. **UpUp 随安装包内置（§1.15，第三版）**：构建时 `pnpm bundle:upup` 把 UpUp 的一个已提交版本（`git archive` + 生产依赖）打进 `vendor/upup`，打包后在 `OpenBuddy.app/Contents/Resources/upup`；启动时 `apps_ensure_bundled` 把它登记为本地 Pi 包。**用户机器上不跑 git / npm、不需要 gitcode 凭据**，新电脑开箱即用。内置 UpUp 跟着 OpenBuddy 一起升级，不能单独更新或卸载，可以停用。
   - 第二版的做法（应用页「安装 UpUp」从 Git 装）已不再是默认路径：§1.14 实测 gitcode 仓库要登录才能克隆，新电脑上必然失败。扩展中心仍可手动装任意 Git 源。
3. **装完与本地 checkout 完全一致**：同一个 agentDir 包记录、同一套 `upupPlugins` 开关与 `toolPolicy`；实测 449 个工具。

### 1.2 UpUp 走 Git 安装

| 环节 | 实现 |
|---|---|
| 安装源常量 | `UPUP_GIT_SOURCE = "https://gitcode.com/lumosaigroup/upup.git"`（`features/apps/AppsPanel.tsx`） |
| 入口 UI | 应用页顶部虚线卡「安装 UpUp · 检查并安装」；**未安装时出现**，已安装自动隐藏 |
| 两步流 | 第一次点击 → `agent_extensions_preview_package`（不落盘）→ 显示「确认安装（N 个工具）」→ `agent_extensions_install_package` |

| 卸载/更新 | 沿用 `apps_uninstall` / `apps_update` |
| 默认安装 | 主进程启动后台调用 `apps_ensure_default`（幂等；失败返回 `error` 不抛错；`OPENBUDDY_DEFAULT_APPS=off` 关闭） |

### 1.8 U6 安装来源记录与回滚（2026-11-27，真实运行）

| 环节 | 实现 | 位置 |
|---|---|---|
| 记录结构 | `AppInstallRecord {source, version?, commit?, at}`；`AppInstallHistory {current, previous?}`；持久化到宿主设置 `appInstalls`，键为 `installKey(source)`（去掉 `#ref` / `@ref`） | `services/apps/install-state.ts`、`services/settings/settings.ts` |
| 快照 | 读包内 `package.json#version`；Git 源再读 `git rev-parse HEAD`（5 s 超时，失败不阻塞） | `host/modules/apps.ts` `snapshot()` |
| 安装 | `apps_ensure_default` 安装后 `recordInstall()`（首次没有 previous） | 同上 |
| 更新 | `apps_update` 升级**前后**各拍快照，`recordUpdate()`：内容变了就把升级前状态记为 previous，**第一次更新后即可回滚**；内容没变不覆盖已有 previous；返回 `{install, canRollback}` | 同上 |
| 回滚 | `apps_rollback`：先移除当前源，再按 `pinSource()` = `<repo>@<commit>` 重装并恢复资源开关；成功后 `previous` 清空；失败尽力回装原源并抛可读错误；无记录时 `rollback_unavailable` | 同上 |
| 查询 | `apps_install_state` 返回全部记录；卸载时清掉对应键 | 同上 |
| UI | 应用卡显示「当前版本 X」（version 或 commit 前 7 位）；有 previous 时显示「回滚到上一版本」；更新/安装走宿主命令以保证记录 | `AppsPanel.tsx`、`app.css`、`client/api/files.ts` |
| 协议 | 新增 `apps_install_state`、`apps_rollback`（`packageSource` ≤4096）；命令总数 **242** | `protocol/src/commands.ts`、`validate.ts` |

**ref 写法用 `@` 而不是 `#`**：实测 Pi `parseGitUrl`，GitHub 等托管站点认 `#ref`，通用 URL（含 `http://127.0.0.1`、gitcode 等）只认 `@ref`，`#` 会被并进 clone URL 导致 `repository not found`。`@` 两种都能到达固定版本。

单测：`install-state.test.ts`(7)、`apps.test.ts` U6(4，共 14)、`AppsPanel.test.tsx` U6(2，共 12)。

### 1.14 新电脑场景：没有 Node.js、没有 gitcode 凭据（2026-11-27，真实运行）

1. **UpUp 的 gitcode 仓库需要登录才能克隆**。空 HOME 下 `git clone https://gitcode.com/lumosaigroup/upup.git` 直接报 `could not read Username for 'https://gitcode.com'`；真实 HOME 去掉凭据助手后同样失败。之前所有「真实 Git 安装」能通过，是因为本机钥匙串里存着 gitcode 账号。**别的用户首次启动的默认安装会失败**，除非仓库改为公开或换成公开的安装源。这一点需要仓库所有者决定，代码里无法解决。

| Pi 包管理器改用 `commandOutput: "capture"`：Pi 为无终端宿主准备的模式，git 不弹凭据提示、错误信息带上 git/npm 输出尾部 | `pi-engine.ts` `packageManager()` |

## §3 设计要点

- **内置应用不是包**：`source:"builtin"`、无 `packageSource`，不参与启停；`apps_list` 排序与去重按 `id@installedPath|source`。
- **Git 安装先预演**：预演不写包记录；确认后才落盘，避免误装。
- **安全边界不变**：交易类 `place_trade_order` / `cancel_trade_order` 仍由 `Permissions.decision()` 最前置拒绝；安装不触碰 `toolPolicy`。
- **离线取舍**：内置 UpUp 不需要网络即可加载（行情等数据工具本身仍要联网）；Git 安装需要网络与凭据。
- **内置与动态副本不共存**：`apps_ensure_bundled` 发现同 id 的 Git/npm 副本时移除它，免得同名工具注册两遍。
