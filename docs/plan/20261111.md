# OpenBuddy 迁移计划：Tauri + Grok → Electron + Pi

- 日期：2026-11-11
- 状态：核心迁移已实现并完成本机集成验证；发布验收与部分兼容命令未完成（详见 §12）
- 目标分支：`feat/electron-pi`
- 目标版本：v1.0.0（Electron 版首个可发布版本）

---

## 1. 目标与结论

### 1.1 目标

1. 删除 Tauri 桌面壳，改为 **Electron**。
2. 删除 Grok 底层引擎（`xai-grok-shell` / `xai-grok-acp-lib` / `vendor/grok-build`），改为 **Pi**（`@earendil-works/pi-coding-agent`）。
3. 保留现有 React/Vite 前端，最大程度复用 52k 行 UI 代码。
4. 首版只覆盖 **核心 MVP**，其余功能后续补齐。

### 1.2 已确认的决策

| 决策项 | 结论 |
|---|---|
| 桌面框架 | Electron（最新稳定 45.x，内置 Node 24.22.2） |
| 引擎 | Pi SDK，运行在 Electron **主进程内**（非子进程 RPC） |
| 前端 | 保留现有 React/Vite，只替换平台调用层与事件类型 |
| 首版范围 | 核心 MVP（聊天、会话、工具、模型/BYOK、文件、权限、MCP/技能/通知） |
| 暂缓范围 | 专家市场、自动化、连接器 CLI、插件市场、云存储、子代理/团队、计划模式、rewind |

### 1.3 非目标

- 不追求与现有 Tauri 版 100% 功能对等。
- 不重写 Pi 引擎，也不把 Pi 移植到其他语言。
- 不保留 Rust 后端作为 sidecar。
- 不保留 `@tauri-apps/*` 运行时依赖。

## 2. 现状分析（已核实）

### 2.1 代码规模

| 区域 | 规模 |
|---|---|
| 前端 `src/` | 约 52,305 行 TS/TSX |
| Rust 后端 `src-tauri/src/` | 约 12,163 行，15 个模块 |
| Tauri 命令 | 124 个 `#[tauri::command]` |
| 前端 `invoke` 调用 | 127 处 |
| `@tauri-apps/*` 导入 | 31 个文件 |
| 对话框调用 | 12 处 `@tauri-apps/plugin-dialog` |

### 2.2 关键耦合

- 引擎：`src-tauri/src/grok.rs` 在专属 OS 线程上运行 `MvpAgent`，通过 ACP mpsc 通道通信。
- 事件：`src-tauri/src/bridge.rs` 发出 `grok://update`、`grok://permission`、`grok://complete`、`grok://turn-error`、`grok://summary`、`grok://subagent`、`grok://mcp-status`、`grok://folder-trust`、`grok://plan-mode`、`grok://permission-mode`、`grok://models-update`。
- 前端事件层：`src/lib/grok-client.ts`（1,136 行）、`src/lib/types.ts`（955 行）、`src/stores/session-store.ts`（688 行）按 ACP 设计。
- 本地能力：`shell_fs.rs`、`connector_cli.rs`、`agent_admin.rs`、`mcp.rs`、`team_mcp.rs`、`automations.rs` 直接使用文件系统与子进程。
- 引擎源码：`vendor/grok-build` 是 git submodule，当前未初始化（目录为空）。

### 2.3 迁移后必然发生的回退

- 安装包体积：约 34MB（Tauri）→ 预计 150–250MB（Electron + Node + Pi）。
- 内存占用：显著高于 Tauri。
- 功能：团队/专家/自动化/连接器/插件/云存储在 MVP 中不可用。
- 图标：Native SDK 讨论期的 207 个自绘图标不适用；Electron 保留 React，因此图标不受影响（本计划保留 React）。

会话/通知/设置 handler 当前集中在 `ipc/handlers/agent.ts`，没有单独的 sessions/notifications 服务文件。

### 3.2 进程与安全

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`（preload 用 `.cjs`）
- 主进程维护命令白名单；preload 仅暴露 `invoke/listen/dialog/window/getPathForFile` 五接口。
- IPC 验证调用方 webContents、mainFrame 与完整受信 URL；原生目录选择授予工作区访问，原生 save 生成一次性导出授权。
- IPC payload 做运行时校验（手写 guard 或 zod）。
- 外部链接只允许 `https/http`，统一走 `shell.openExternal`。
- API Key 使用 Electron `safeStorage` 加密存储。

## 4. Pi SDK 接入设计

### 4.1 初始化

```ts
import {
  createAgentSession,
  DefaultResourceLoader,
  ModelRuntime,
  SessionManager,
} from "@earendil-works/pi-coding-agent";

// Pi 1.5.2：使用纯内存 CredentialStore，避免 SDK 写出明文 auth.json。
const modelRuntime = await ModelRuntime.create({
  credentials: {
    read: async () => undefined,
    list: async () => [],
    modify: async (_id, fn) => fn(undefined),
    delete: async () => {},
  },
  modelsPath: null,
  refreshOnCreate: false,
  allowModelNetwork: false,
});
// providers.json 经校验后调用 registerProvider；safeStorage 解密后仅注入运行时。
// await modelRuntime.setRuntimeApiKey(providerId, decryptedKey);

const resourceLoader = new DefaultResourceLoader({
  cwd: workspace,
  agentDir: piDir,
  extensionFactories: [permissionExtension, projectTrustExtension],
});
await resourceLoader.reload();

const { session, modelFallbackMessage } = await createAgentSession({
  cwd: workspace,
  agentDir: piDir,
  modelRuntime,
  sessionManager: SessionManager.create(workspace, sessionDir),
  resourceLoader,
  tools: ["read", "bash", "edit", "write", "grep", "find", "ls"],
});
```

### 4.2 事件转发

主进程订阅 Pi 事件，序列化后发送到渲染进程：

| Pi 事件/服务结果 | 实际渲染进程通道 |
|---|---|
| Pi 原始会话事件（含 message_update、tool_execution_*、agent_settled） | `agent://event`，载荷 `{ sessionId, event }` |
| 扩展 tool_call 权限请求 | `agent://permission` |
| assistant error / send 异常 | `agent://turn-error` |
| bindExtensions onError | `agent://error`，客户端转换为带 sessionId 的 onTurnError（审查补齐） |
| 会话命名 / 模型配置 / 工作区信任 / 权限模式 / MCP 状态 | `agent://summary` / `agent://models-update` / `agent://folder-trust` / `agent://permission-mode` / `agent://mcp-status` |

前端由原始 `agent_settled` 派生完成通知，`agent://update/tool/complete/...` 虽在白名单保留但当前主链不单独发送。自动 retry 与 compaction 按 Pi 默认启用（审查移除误留的 false 覆盖）；重试中间 error 不立即报最终失败，最终非 aborted settled 才发 turn-error，后续成功清除临时错误。

规则：
- `message_update` 是增量，按 `contentIndex` 累积；在 `text_end` / `toolcall_end` / `message_end` 用完整内容覆盖。
- UI 的“空闲”状态以 `agent_settled` 为准，不以 `agent_end` 为准。

### 4.3 会话

- 新会话：`SessionManager.create(cwd, sessionDir)`。
- 列表：`await SessionManager.list(cwd, sessionDir)`。
- 打开：`SessionManager.open(path, sessionDir)`，先验证会话 ID 对应路径在应用会话目录内。
- 实际实现通过 `createAgentSession(...)` 替换当前会话，先 abort/清审批/发送 session_shutdown/dispose，再重新 `subscribe` 和 `bindExtensions`；没有使用 `AgentSessionRuntime` 或 `createAgentSessionRuntime`。
- 历史重放发送 `message_start` / `message_end` 与 `agent_settled { replay: true }`，前端抑制重复缓存与完成通知；分叉暂缓。

### 4.4 模型与 BYOK

- 配置保存在 `providers.json`，使用 `registerProvider` / `unregisterProvider` 注册进程内模型；不生成 `models.json`。
- 当前支持 OpenAI Chat Completions / Responses 与 Anthropic Messages 协议；未实现 Google 原生协议。在线兼容性尚未验证。
- 运行时密钥：`await modelRuntime.setRuntimeApiKey(provider, key)`；SDK CredentialStore 不落盘。
- SDK 内置能力读取：`modelRuntime.getModels()`；选择模型：`modelRuntime.getModel(provider, id)`。
- `providers_*` 校验并保存配置后刷新 ModelRuntime；按 providerKind 继承内置模型能力，自定义能力可覆盖。未知价格返回 `pricingKnown: false`，不宣称免费。

### 4.5 权限

Pi 没有内置权限系统。使用内联扩展：

```ts
const permissionExtension = (pi: ExtensionAPI) => {
  pi.on("tool_call", async (event) => {
    const decision = await requestPermissionFromRenderer(event);
    if (!decision.allow) return { block: true, reason: decision.reason };
    return undefined;
  });
};
```

渲染进程复用现有 `PermissionDialog`；主进程保存 pending 请求并与 IPC 响应关联。

### 4.6 MCP / 技能 / 命令

- MCP：读写 `<piDir>/mcp.json`，在 SDK 中加载 `createMcpExtension()`，会话创建后 `session.bindExtensions()`；OAuth 使用 `@earendil-works/pi-mcp/oauth` 公开 PKCE/state/loopback/DCR/token API，token/refresh/clientSecret/PKCE 状态经 safeStorage 加密保存。
- 技能：使用 SDK `loadSkills({ cwd, agentDir: piDir, skillPaths, includeDefaults: true })`，配置路径与禁用列表保存到 `openbuddy.json`。
- 斜杠命令：当前 `commands_list` 来自已启用技能的 `skill:<name>`，没有调用未核实的 `session.getCommands()`；任意扩展命令/UI input/select 桥接不在已验证范围。

### 4.7 目录隔离

| 内容 | 位置 |
|---|---|
| Pi 配置 | `app.getPath("userData")/pi/` |
| 会话 | `app.getPath("userData")/pi/sessions/` |
| 认证 | `app.getPath("userData")/pi/credentials.enc.json`（仅 safeStorage 密文；无 auth.json） |
| 模型 | `app.getPath("userData")/pi/providers.json`（内存注册到 ModelRuntime；无 models.json） |
| MCP | `app.getPath("userData")/pi/mcp.json` |

不读写用户 `~/.pi`，除非用户显式指定。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 包体积 150–250MB | 与现有卖点冲突 | 文档明确说明；后续可评估 asar 压缩、按需下载 |
| `session-store.ts` 重写 | 前端最大工作量 | 先写事件适配层，再做 UI 对接；用录制事件回放测试 |
| Pi 无权限系统 | 安全风险 | `tool_call` 内联扩展 + 默认拒绝高危工具 |
| 功能回退 | 用户流失 | 明确 MVP 边界；后续按优先级补齐 |
| ESM/asar 打包 | 启动失败 | P0 就验证打包链路；`asarUnpack` 白名单 |
| Electron 安全 | 远程代码执行 | sandbox + contextIsolation + 白名单 + CSP |
| Pi 版本升级 | API 变动 | 锁定版本；升级前跑 SDK 集成测试 |
| macOS 公证 | 无法分发 | 提前配置 hardened runtime 与 entitlements |

### 回退方案

- 迁移期间保留 `main` 分支的 Tauri 版本。
- `feat/electron-pi` 按 P6 删除旧栈；旧版由迁移基线/历史提交保留。回退应切换旧版分支或另建回退变更，不在新运行树保留第二套 Rust/Grok 引擎。此处修正原“先删除旧栈/合并前不删除”的矛盾。
- Pi coding-agent 与 pi-mcp 精确锁定 `1.5.2`，升级单独审查。
