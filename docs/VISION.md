# 让每个人都能拥有自己的 Buddy

> 本文是 OpenBuddy 的产品主张与路线图。它描述我们**要成为什么**，不是对当前版本的完成度承诺；实际可用性请看 [功能状态总表](FEATURE-STATUS.md)。

## 我们要解决的问题

今天的 AI 工具大多是"一次性聊天"：关掉窗口就忘了你是谁，没有性格，不能积累，数据留在别人的服务器上。你换一个工具，就要从头解释一遍自己。

OpenBuddy 的出发点很简单：**AI 助手应该是你的，不是借来的**。

一个真正的 Buddy，应该像一位长期搭档——认识你、记得你、有脾气、能动手、知道什么不能碰，而且住在你的设备上。

## Buddy 的五个部分

| 部分 | 它是什么 | OpenBuddy 里对应的能力 |
| :--- | :--- | :--- |
| 记忆 | 跨会话记得你的项目、偏好与决定 | 本地会话、项目说明、快照、检查点、JSONL 导出 |
| 人格 | 有自己的说话方式和专业背景 | 专家 / 人设、团队子会话、提示词与能力包 |
| 手脚 | 能真的读写文件、调用工具 | 工具调用、MCP 连接器、技能与脚本 |
| 自主 | 不用你盯着也能干活 | 自动化（定时 / 文件触发）、修订号与失败重试 |
| 边界 | 知道什么该问、什么绝不做 | 审批卡片、受保护路径、本地密钥、脱敏诊断 |

这五部分不是未来设想——它们在当前代码里都有对应实现（见功能状态总表的"条件可用"项）。我们要做的是把它们**组织成一个开箱即用的 Buddy 体验**。

## 为什么必须本地优先

"自己的 Buddy" 有三个前提，缺一不可：

1. **数据在你手里**：会话、项目、产物、快照都在本机应用数据目录。
2. **钥匙在你手里**：BYOK，API Key 由系统钥匙串加密，不进日志、不进导出包。用本地模型时可以全程离线。
3. **规则由你定**：每个工具调用都可以审批；`.env`、`.ssh`、`*.pem` 等路径任何模式下都拒绝写入。

云端助手可以很方便，但它很难成为"你的"——因为决定它记忆去留的是服务商，不是你。

## 体验闭环

我们想让第一次使用短到没有心理负担：

1. **挑一个 Buddy**：从模板库选"写作搭子 / 代码同伴 / 资料管理员"，而不是面对空白输入框。
2. **给它一个名字和边界**：改人设、指定工作目录、选模型。
3. **一起干活**：流式对话 + 审批卡片，产物落在右侧工作台。
4. **它记住你**：项目说明与技能积累下来，下次不用重讲。
5. **你把它分享出去**：导出一个 Buddy 包，别人导入就能用——**每一次分享都是一次产品曝光**。

这就是增长飞轮：Buddy 越好用 → 越多人分享模板 → 越多人拥有自己的 Buddy → 模板生态越丰富。

## 路线图

| 阶段 | 目标 | 状态 |
| :--- | :--- | :--- |
| 底座 | 对话 / 审批 / 模型 / 产物 / 专家 / 技能 / 自动化在 Electron 上跑通 | 已具备，待发布验证 |
| 体验 | "60 秒创建 Buddy" 引导、模板库、Buddy 卡片式首页 | 设计中 |
| 分享 | Buddy 包导出 / 导入、一键分享链接、社区模板榜 | 设计中 |
| 协作 | 多个 Buddy 组成团队、跨设备同步（可选、显式授权） | 更远期 |

## 衡量什么

我们不用"日活时长"衡量 Buddy 是否成功，而看三件事：

- **首次 Buddy 创建耗时**：目标 < 60 秒。
- **7 日回访率**：用户是否回来找"同一个" Buddy。
- **模板分享率**：有多少 Buddy 被导出并给到别人。
