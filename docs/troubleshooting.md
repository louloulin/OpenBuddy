# 故障排查

先做三件事：确认版本（设置 → 关于）、确认模型可用（设置 → 模型 → 测试）、生成诊断报告（设置 → 帮助与反馈）。

## 启动与白屏

- 页面显示「这个页面遇到了问题」：草稿与历史都还在，点「重试」；仍失败时点「复制诊断」，把报告发给维护者。
- 启动即退出：查看 `<数据目录>/logs/` 最新日志；主进程异常、渲染进程崩溃与加载失败都会记录。
- 配置损坏导致无法启动：应用会先从快照恢复；没有快照时损坏文件被隔离为 `*.corrupt-<时间戳>`，可从「数据管理」回滚。

## 模型请求失败

| 现象 | 排查 |
|---|---|
| 401 / 403 | API Key 是否过期、Base URL 是否与密钥匹配 |
| 404 | 模型名是否存在于该服务商；Base URL 是否需要 `/v1` |
| 超时 / 连接失败 | 代理环境变量（`HTTPS_PROXY`/`HTTP_PROXY`）是否可用；本地模型地址是否正确 |
| 429 | 触发限流，稍后重试或换模型 |
| 图片输入报错 | 当前模型不支持图片，换支持视觉的模型 |

## 工具审批反复弹出

- 受保护路径（`.env`、`.ssh`、`*.pem` 等）在任何模式下都会拒绝写入；需要时在 设置 → 安全中心 调整规则，而不是关闭审批。
- 「本会话允许」只对当前任务生效，新任务会重新询问。

## 专家包/技能导入失败

- 本地包：确认目录包含 `plugin.json` 或 `SKILL.md`。
- 链接导入：只允许 HTTPS；私网、回环与带凭据的 URL 会被拒绝（SSRF 防护）。
- 重复导入：按内容摘要去重，会直接打开已有专家。
- 安装后的技能在 `<数据目录>/skills/`；源目录删除不影响已安装技能。

## MCP / 连接器授权

- 授权尝试有到期时间；弹层关闭即取消。
- 回调地址使用本机回环端口，需要浏览器能访问 `127.0.0.1`；公司代理可能拦截。
- 失败时重开一次授权尝试；先把诊断报告里的错误码记下来。

## 自动化没有触发

- 任务状态是否为「启用」；工作区是否存在且已授权。
- 文件触发依赖监听路径；被监听文件在任务停用期间的变化不会补跑。
- 运行记录里的失败条目可以「重试」，会以新记录写入并回链原记录。

## 数据导出/恢复

- 恢复包不含密钥，恢复后需重新输入 API Key。
- 恢复与回滚在重启后生效（服务内存态不会热替换）。
- 「导出全部数据」包上限 20 MB；会话历史用 JSONL 单独导出。

## 性能与内存

- 冷启动约 2–3 秒、空闲工作集数百 MB 属正常范围；长会话内存持续上涨时，先导出 JSONL 再新开会话。
- 开发者可用 `pnpm check:perf` 检查包体与懒加载块，用 E2E 的「性能预算」步骤查看冷启动/一轮/内存实测。

## 还有问题

设置 →「帮助与反馈」→「生成诊断报告」：报告本机生成、脱敏，先预览再复制/保存。请附上复现步骤、版本号与操作系统。
