OpenBuddy 跨 Buddy 协作流 v1 · 2026-08-31 · Alice 双向 Bob via Federated Room Grant

两个用户的 OpenBuddy 如何端到端协作：发现 → 信任 → 授权 → 委托 → 验收。整套流程贯穿三层产品（personal / organization / network）、三平面（Experience / Control / Execution）和 10 条不变式。私钥 / 凭证 / 完整 session body 从不进入跨边界网络，所有副作用走 SideEffectIntent + Federated Room Grant + 独立 Verifier。

Alice 侧（请求方） Bob 侧（提供方） 本地 Relay / 沙盒 审计与证据 失败 / 撤销

反例 vs 正例：Discovery、Authority、Verifier 三处最容易出错

反例（破坏不变式）

  • 把 private:prompt / credential:token / 完整 session body 放进 envelope → 私钥泄露
  • 只看 Agent Card 展示就执行任务 → Discovery 当成 Authorization
  • Provider 自己 verify 自己交付的 artifact → Provider 等于 Verifier
  • Federated Room Grant 颁发后从不 revoke → 过期委托继续投递
  • 用同一个 BuddyIdentity 跑 personal 和 org 任务 → AgentIdentity 与 AgentProfile 混淆
  • 不读 trust root 直接信任 Agent Card 的 verified 标志 → 持久化信任被绕过

正例（守住 10 条不变式）

  • envelope 仅携带 stableId + digest + capability + refs
  • Discovery 不等于 Authorization：每次执行都重新检查 grant + membership + expiry + nonce
  • 独立 Verifier 强制 id 不属于 provider, requester
  • Federated Grant TTL + revoke 双向；过期自动撤销
  • BuddyIdentity 不等于 AgentProfile 不等于 Pi AgentSession 三层独立
  • 每次 trust 验证都重读 trustRoots，不依赖持久化标志

跨 Buddy 协作必须强制的 10 条不变式

1 · effectivePolicy

owner ∩ org ∩ task ∩ capability；任何 deny 不能被覆盖。

2 · EventStore 唯一事实源

UI 是事件投影；跨 Buddy 也从本地 EventStore 重建。

3 · Discovery 不等于 Authorization

Agent Card / Offer / Proposal 都不等于可执行授权；grant 必含 principal + scope + expiry。

4 · Provider 不是 Verifier

verifier 必须独立；同 ID 视为 fail。

5 · 三层 Identity 分离

BuddyIdentity 不等于 AgentProfile 不等于 Pi AgentSession。

6 · 私有不跨边界

session / 凭证 / 完整 prompt / connector config 不进入 envelope。

7 · Wake 携带 ID + reason + nonce

消费时重读 authority + 检查 membership / expiry / revocation / nonce。

8 · 副作用一次性消费

每个不可逆外部副作用都有 SideEffectIntent 引用 + fingerprint。

9 · Federated Room Grant 必含

跨组织 Project Room 必须有 Federated Room Grant 才能投递。

10 · 公网 Relay / 结算 not_configured

deployment / payment / settlement / 无人值守不可逆副作用显式 not_configured。

用户可观察的 UI 入口（OpenBuddy 助理工作台）

  • 助理·开放网络：NetworkList + BuddyDirectory（本人 / 组织 / Peer 三栏）
  • 助理·Rooms：FederatedGrantList 跨/同组织徽章（橙 + 颁发方/主体/数据范围/动作/操作 显式）
  • 助理·证据与审计：独立 Verifier 高亮；每条 delivery 附 verifier.id 与 digest
  • 助理·副作用恢复：跨组织 SideEffectIntent 列表；revoke + 一次性消费
  • 项目详情 → 跨组织交付 / 工作流黑板：项目维度 Federated Grant + Workflow DAG
  • Composer 斜杠命令：/buddy-propose、/federated-grant 两条 plugin-shipped 入口
  • 消息 footer：委托给 Buddy（replayable TaskEnvelope，不复制完整 prompt）
