Primary user journey

01 · Request用户在助理工作台描述目标，选择个人 / 组织 / 开放模式。
→
02 · ContractBuddy 生成任务合同，展示能力、数据范围、预算和验收条件。
→
03 · Delegate发现并委托一个或多个 Buddy，策略引擎计算最小权限。
→
04 · Execute独立 Session 执行，Room 只看到授权摘要与状态。
→
05 · Verify产物进入证据包，人工或独立 verifier 验收；所有事件可重放。

结论：全局控制面在“助理”，项目协作做上下文投影

不改变：现有 Sidebar 一级导航、项目任务/资产、ChatView、专家·技能·连接器、自动化和邮件路径。全局新增：在“助理”下提供总览、收件箱、日程、跨项目任务、Rooms、助理与 Buddy、开放网络、能力与策略、证据与审计；未来能力通过受校验的 Assistant Renderer Contribution 注册为“助理·子菜单”，不增加新的一级菜单。项目新增：项目详情页提供“Buddy 协作”Tab，只显示当前 projectId 的任务、执行、交付和验证；个人/组织项目任务分别进入独立 Project Room，Provider、Artifact、Evidence 复用同一 Room 边界。两处复用同一 collaboration:propose / collaboration:execute、Coordinator、Provider 与 Verifier，不复制第二套执行状态。Personal Provider Registry 可组合 TeamRunner、记忆、邮件摘要、自动化快照和 Calendar Capability；日程写入必须变成审批后的协作任务。授权链：Agent Card 只用于发现，A2A 请求必须重新进入 Main-owned Runtime；Relay 每次按 credential、scope、Grant、capability token、expiry、presence lease 和持久化 nonce 校验，失败消息可经 outbox 重试但不同 message 不得复用 nonce。当前本地 facade/RemoteRelay/WebSocket seam 已有测试证据；本地 Relay 重启可以恢复撤销索引，但这不等于公网 revoke propagation。公网 Relay、签名 Agent Card、公钥信任、公共目录、支付、结算和开放网络 Project Room 仍保持关闭。
