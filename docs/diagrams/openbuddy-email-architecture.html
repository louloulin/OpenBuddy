Core principles

Mail ≠ Notification

邮件拥有独立的 account/thread/draft/attachment 领域模型；Reply Zero 待回复项以只读投影进入助理统一 Inbox，不伪造协作事件。

Label ≠ Workspace Tag

Gmail/Graph 原生 Label 由 provider 同步；OpenBuddy Workspace Tag 保存业务上下文。邮件支持 Any/All 检索，项目/计划/任务支持本地标签编辑、统一搜索命中和 `WorkspaceTagRef` 派生；后续再扩展文档和协作对象，并由各自权限控制正文。

MCP-first, provider-neutral

复用现有 MCP client、OAuth 和凭据边界。QQ Mail、Gmail、Graph 和 IMAP/SMTP 都是 adapter；写信与邮件管理能力分开声明，不侵入 UI。

Draft before send

AI 默认只能读和起草。发送是高风险动作，需要展示完整摘要、用户确认、一次性 token 和审计 receipt。

Primary request path

01 · Ask用户说“找本周客户邮件并拟回复”，或在邮件工作区搜索。
→
02 · Read / TriagePi tool 调用 Email domain，按账号和过滤条件查线程，并只读计算分诊。
→
03 · Plan / DraftAI 可提出归档/已读/星标/标签计划，或运行已保存规则；先 dry-run 预览；写信则先创建 draft。
→
04 · Confirm用户确认计划或草稿后获得一次性 token；过期、变更或 provider 不支持都会停止执行。
→
05 · Undo windowMain 将已确认草稿写入持久队列；5 秒内可撤回，窗口结束后才调用 provider。
→
06 · Send队列 worker 验证指纹后调用 provider，记录 receipt；重启后继续处理。

Threat boundaries

Prompt injection

邮件正文和附件文本是外部不可信输入，不能改变系统策略、权限或发送确认。

Data minimization

日志只保存 ID、provider、操作和状态；正文、token、附件内容禁止进入 telemetry。

Credential isolation

只使用 OpenBuddy 的 MCP OAuth/凭据机制，不读取 WorkBuddy 私有 token 或数据库；profile 只映射工具名，不代表真实 OAuth 已验证。用户消息中暴露的 QQ 授权码不得使用，必须撤销并轮换。

Definition of done

Correctness

线程、未读、标签和发送 receipt 与 provider 一致；重复刷新不重复写入。

Safety

无 token 拒绝发送；正文不进入日志；HTML 和附件均有安全降级。

Extensibility

第二 provider 只实现 adapter；关闭邮件 capability 不影响普通会话和通知中心。

错误码语义

capability_denied

请求方法不在 policy 允许集合中；返回时同步给出 reason 与 method 名称，方便 UI 给出明确提示。

account_denied

policy.accountIds 不包含目标 accountId；用于协作 Inbox 跨账号分享场景。

scope_denied

policy.scopes 不覆盖当前 method 的所需 scope（读 / 写 / 分享 / 提醒 / 摘要）。

集成路径

协作 Inbox

从 emailSharedRef 回链时使用 readonly() policy，避免协作面板误触发外发或修改。

项目反查
