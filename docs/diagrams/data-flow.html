🔄 OpenBuddy 数据流分析

用户 Prompt → LLM 响应 完整链路

1
用户输入
用户在 Composer 组件中输入文本，可附带文件上下文、图片等
src/App.tsx → Composer.tsx
│
2
IPC 调用
Composer 调用 window.api.invoke("agent:prompt", { text, context })，通过 contextBridge 安全传递到主进程
src/lib/platform/electron-api.ts → electron/preload/index.ts
│
3
IPC 路由
ipc.ts 白名单处理器接收请求，验证参数，路由到 agent-host.ts
electron/main/ipc/index.ts
│
4
Pi AgentSession
agent-host.ts 调用 Pi AgentSession.prompt()，Pi 运行时决策下一步动作（调用工具或直接回复）
electron/main/agent/agent-host.ts
│
5
工具调用
Pi 决策调用工具（如 read_file），通过 Cordis 上下文查找对应的 Service 并执行
packages/fs/openbuddy-fs-local/ → @openbuddy/storage
│
6
权限检查
检查路径是否在用户已授权信任的文件夹内。未授权则发出 permission:request 事件，渲染端弹出模态框请求用户确认
packages/capability/openbuddy-folder-trust/
│
7
LLM 调用
Pi 用工具结果调用 LLM（支持 Anthropic / OpenAI / NewAPI / 自定义 Provider），BYOK 模式
@earendil-works/pi-ai → Provider Registry
│
8
流式响应
LLM 流式返回，AgentSession 发出 pi://message-delta 事件
@earendil-works/pi-coding-agent
│
9
事件桥接
pi-event-bridge.ts 通过 webContents.send 将事件转发给渲染端
electron/main/agent/pi-event-bridge.ts
│
10
UI 渲染
ChatView.tsx 监听 pi://* 事件，将增量内容追加到可见消息，支持 Markdown、代码高亮、数学公式、图表渲染
src/stores/session-store.ts → @openbuddy/ui-conversation
│
11
持久化
完成时 AgentSession 发出 pi://done，结果存入 @openbuddy/capability-memory (SQLite)
packages/runtime/openbuddy-storage/ → ~/.config/openbuddy/
渲染层
主进程
能力层
安全检查
持久化

📡 Pi 事件类型

pi://message-delta
消息增量内容，流式文本片段
pi://tool-call
工具调用请求（工具名 + 参数）
pi://tool-result
工具执行结果
pi://plan-update
计划模式更新
pi://permission
权限请求（文件夹信任等）
pi://done
任务完成
pi://error
错误事件
pi://ready
会话就绪（sessionId + cwd）
