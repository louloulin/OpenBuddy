OpenBuddy 分布式多智能体协作架构 v3 · 2026-08-31 · Buddy Control Plane

每个 OpenBuddy 用户持有一个持久 Personal Buddy；同一内核在团队/企业协作和开放 Buddy 网络中复用。三层产品共用同一事实源（CollaborationRuntime + JSONL EventStore）和同一授权链（effectivePolicy = owner ∩ org � task ∩ capability）。差异只来自信任、策略和传输。

体验面 控制面 执行面 网络/联邦 安全边界 插件化模块

三层产品个人 → 组织 → 网络，逐层叠加信任和策略，不复制执行

① 个人生产力网络 personal

用户本人的 Personal Buddy，作为默认 operator；不是公共 bot。

  • 能力：日程 / 邮件 / 记忆 / 任务 / 连接器
  • 可见性：private/local · personal-room
  • 副作用：必须显式用户批准（SideEffectIntent）
  • 典型动作：起草回复、预约日程、汇总信息、生成本地 artifact

② 团队/企业协作 organization

多个成员的 Buddy + Org Coordinator，统一权限、审批、审计、知识隔离。

  • 协作单元：project-${digest} 稳定 Room ID
  • 控制面：成员/委托/审批/Workflow/Evidence/独立 Verifier
  • 关键约束：Provider ≠ Verifier；verifier 必须独立
  • 典型动作：项目研究、跨成员汇总、批量邮件草稿、冲突日程

③ 开放 Buddy 网络 network

发现、谈判、委托、交易服务；公网 Relay、支付、结算显式 not_configured。

  • 接入：Agent Card 发现（≠ 授权）+ Federated Room Grant 精确授权
  • 可见性：directory / known_peers / public
  • 签名：Ed25519，token 绑定 subject/scope/task/capability/dataScopes/actions/expiry
  • 典型动作：跨组织研究、公开能力调用、Bid/Award 协商

10 条不变式产品/技术必须共同遵守，代码全程强制

  • 1.effectivePolicy = owner ∩ organization ∩ task � capability
  • 2.EventStore 是唯一事实源；UI 是事件投影
  • 3.Discovery ≠ Authorization：Agent Card ≠ 可执行授权
  • 4.Provider ≠ Verifier：provider 不能自我验收
  • 5.AgentIdentity ≠ AgentProfile ≠ Pi AgentSession
  • 6.私有 session/凭证/完整 prompt 不进入跨边界网络
  • 7.每次 wake/通知携带 ID + principal + reason + nonce
  • 8.不可逆外部副作用有 SideEffectIntent + 一次性消费
  • 9.跨组织 Project Room 必须有 Federated Room Grant
  • 10.公网 Relay/支付/结算：显式 not_configured
