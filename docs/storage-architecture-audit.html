OpenBuddy Storage Architecture Audit

This offline, static artifact records the storage ownership boundary used by the OpenBuddy acceptance checks.

Ownership

DataOwnerBoundary
Structured metadata, events, projections and migrationsOpenBuddy SQLite storageMain-process storage package
Conversation transcriptPi JSONL session storePi runtime/session boundary
Credential valuesSecretStore / OS keychainNever persisted in SQLite or renderer state
Large files and artifactsContent-addressed object storeExplicit service/API access only

Safety invariants

  • SQLite access is centralized in the storage package and uses parameterized statements.
  • Transactions, migrations, backups and integrity checks fail closed on errors.
  • Renderer code accesses storage through typed Main-process contracts.
  • Secrets, tokens, passwords and cookies are excluded from diagnostics and projections.
  • OpenClaw runtime data is outside this local acceptance scope and remains not-run.

Evidence and reproducible commands are recorded in docs/storage-verification-report.md.
